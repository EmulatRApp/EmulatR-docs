Configuring Guest Networking (OpenVMS)

Once EWA0 is bridged to a host adapter (see Networking (EWA0) and Naming the Host Adapter), the guest still has to be configured like any AlphaServer on a LAN: the console link mode, the LAN device, a TCP/IP address and, if DECnet runs, a DECnet address. This page gives the commands in the order you use them.

 

1. Launch with the host adapter bound

Normally there is nothing to do: with EMulatR_NET_ADAPTER unset, EMulatR picks the host's dedicated adapter by itself and logs EWA0 network backend: auto-selected. Name the adapter only when the host has more than one dedicated adapter. The value is a substring of the adapter's device name or description: EMulatR_NET_ADAPTER="I219-LM"

 

Confirm it in the run log. A bound adapter prints EWA0 network backend ATTACHED to '\Device\NPF_{...}' via Npcap. The line EWA0 network backend: no adapter attached means the guest has a working NIC with no wire: everything below can be configured, but no frame leaves the host.

 

2. Plan unique addresses

Every EMulatR instance on the same LAN needs its own IP address and, if it runs DECnet, its own DECnet address. Choose IP addresses outside the router's DHCP range, or reserve them in the router. An example plan for a 192.168.1.0/24 network whose gateway is 192.168.1.254:

MAC addresses: every EMulatR EWA0 presents the same default hardware address, 08-00-2B-E5-40-00. When DECnet Phase IV starts it replaces the current address with one derived from the node's DECnet address (AA-00-04-00-xx-yy), so instances with different DECnet addresses also have different MAC addresses. Instances that do NOT run DECnet share the default address, and only one of them may be on the LAN at a time.

 

3. Set the link mode at the console

At the SRM prompt, before booting, select 100 Mb/s full duplex:

P00>>> set ewa0_mode FastFD

P00>>> show ewa0_mode

P00>>> b dka200 -fl 0,1

 

The setting is stored in the console NVRAM and survives restarts. The DS10 and DS20 prompt is >>>; the ES40 prompt is P00>>>. Use your own boot device in the boot command.

 

4. Set the LAN device in LANCP

To change the running device, and to make the same setting permanent for the next boot:

$ MC LANCP

LANCP> SET DEVICE EWA0 /SPEED=100 /FULL_DUPLEX /NOAUTONEGOTIATE

LANCP> DEFINE DEVICE EWA0 /SPEED=100 /FULL_DUPLEX /NOAUTONEGOTIATE

LANCP> SHOW DEVICE EWA0 /CHARACTERISTICS

 

SET changes the running device; DEFINE writes the permanent database used at the next boot. The result should include:

08-00-2B-E5-40-00 Default MAC address (Hardware LAN address)

Yes Full duplex operational

AA-00-04-00-03-04 MAC address (Current LAN address)

100 Line speed (mbps)

Disabled Auto-negotiation

Link Up Link state

 

Use a fixed speed, not auto-negotiation. The emulated DE500 does not yet present a link partner, so auto-negotiation has nothing to negotiate with and settles on 10 Mb/s half duplex. The FF-FF-FF-FF-FF-FF line in the output belongs to the multicast list (broadcast); it is not a second MAC address.

 

5. Set the TCP/IP address

The TCP/IP interface for EWA0 is WE0. Either run the menu-driven @SYS$MANAGER:TCPIP$CONFIG, or set the address directly:

$ TCPIP SET CONFIGURATION INTERFACE WE0 /HOST=192.168.1.48 /NETWORK_MASK=255.255.255.0

$ TCPIP SET CONFIGURATION ROUTE /DEFAULT /GATEWAY=192.168.1.254

 

The configuration database is read when TCP/IP starts, so restart TCP/IP Services (or reboot) for the new address to take effect.

 

6. Check the DECnet address

If DECnet Phase IV runs, read the current MAC address from the LANCP output in step 4. AA-00-04-00-xx-yy encodes the DECnet address as the 16-bit number yyxx (low byte first): area = number / 1024, node = number mod 1024. For example AA-00-04-00-03-04 is 0x0403 = 1027 = node 1.3. Two nodes with the same DECnet address on one LAN have the same MAC address, and neither works reliably.

 

7. Verify

From the guest, ping another machine on the LAN:

$ TCPIP PING 192.168.1.254

 

In Wireshark on the host, this display filter shows only DEC traffic -- DEC hardware addresses, DECnet Phase IV addresses, DEC multicast and the DEC protocol types (MOP, DECnet, LAT, cluster) -- plus the IP addresses you name:

eth.addr[0:3] == 08:00:2b || eth.addr[0:3] == aa:00:04 || eth.addr[0:3] == ab:00:00 || eth.addr[0:3] == 09:00:2b || eth.addr[0:3] == 00:00:f8 || (eth.type >= 0x6000 && eth.type <= 0x6009) || ip.addr in {192.168.1.48, 192.168.1.99}

 

A guest's periodic traffic arrives far less often than on a real system. EMulatR's guest clock runs slower than real time by design, so a DECnet end-node hello that a real AlphaServer sends every 15 seconds appears only every several minutes from an EMulatR guest.
