Warp

Firmware waits for hardware by spinning: during probes and resets the SRM busy-waits on the cycle counter (RSCC) for a fixed interval. Executed instruction by instruction, those calibrated delays are pure cost. Warp recognises each such loop and collapses it -- the emulated cycles the loop would have spent are skipped rather than executed.

How it behaves

•Always on. The warp and its census run on every boot; there is nothing to enable.

•Discovered once, reused after. The first boot of a firmware image finds its delay loops and pays a one-time discovery cost. Every later boot loads what was found, confirms a known loop after a few re-reads instead of the full spin, adds anything new, and writes the result back at clean exit.

•Stored beside the firmware. The findings live in <stem>_warp.json, a run product like the flash NVRAM: it never ships and is never copied between machines. A fresh install builds its own on first boot.

•Bound to the exact firmware. The file records the size and FNV-1a hash of the image it was measured against. A census for different firmware bytes is refused as stale, renamed to <stem>_warp.stale-<fnv64>.json, and replaced at clean exit.

•Idle loops are paced, not skipped. A block loop that has been reviewed and marked audited is warped at most one timer tick per 12000 executed instructions, which keeps an idle guest near real time and every run reproducible. No loop is audited in this release, so none is paced by default.

Turning it off for a comparison

Set EMULATR_UDELAYWARP=0 before starting EmulatR to run without the warp; the census is still loaded and saved. This exists so the warp's effect can be compared in two runs rather than two builds. Any other value, or none, leaves the warp on.

Timing runs

Because each clean exit updates the census, two runs of the same workload are only comparable if they start from the same census. Make <stem>_warp.json read-only: a read-only census is used but never rewritten, so every run starts from identical findings. Discard the first boot after a firmware change -- it is the one that pays the discovery cost.
