Release Notes

EmulatR brings the real DEC/Compaq/HP Alpha SRM console firmware to life on emulated Tsunami/Typhoon-class hardware. This chapter records what each release delivered: what landed, what was fixed, and what was still incomplete when the build shipped. Every release has its own page beneath this topic, newest first, so the current release is always the first entry in the chapter.

 

How to read a release page

A release page is written against the build it names and is not revised afterward. Everything on it - the capabilities claimed, the packaging described, the known limitations listed - describes EmulatR as it behaved at that build, and is kept as the record of what was delivered then, not as current instructions. When a limitation is lifted or a behavior changes, the change is recorded on the newer page rather than by editing the older one. Read the newest page for the state of the emulator today.

 

Release pages are written for the operator. They say what changed at the console, in the guest, or in the launcher. The granular developer history - commit ranges, JRN references, internal refactoring - belongs in CHANGELOG.md and is deliberately left out here.

 

Most pages follow the same shape, though a release only carries the sections it needs:

 

Section

Contents

Highlights this cycle

The two or three results that define the release, stated in terms of what the machine now does.

Added

New capability: device models, console facilities, runtime controls, data files.

Changed

Behavior that differs from the previous release, including defaults that moved and anything a returning operator must do differently.

Fixed

Defects closed, given by the symptom each one produced rather than by the code that changed.

Known limitations

What is incomplete, unimplemented, or deliberately gated in that build, and the workaround where one exists. Read this section before filing a defect.

 

Identifying your build

The version and build number are compiled into the executable and displayed when it runs. That displayed string is the authoritative identifier: it names the binary actually running, whatever the installation directory or file names suggest. To find which release page applies to an installation, start the emulator and read the version it reports.

 

Quote that string exactly as displayed when reporting an issue. The build number distinguishes releases that share a version, and a release page applies only to the build it names.

 

Firmware is never included

No release of EmulatR ships SRM firmware. The images are licensed, so you supply your own; a release page describes the emulator, never the firmware it loads. Anything derived from a firmware image at run time - the calibrated-delay census, the flash NVRAM, the console badge figure - is likewise generated on your machine and never shipped.
