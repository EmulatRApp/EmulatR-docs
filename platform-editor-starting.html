Starting the Platform Editor

Where it is

The editor is in the editors folder beside the emulator:

<run-dir>/editors/platedit_wx.exe

 

With it in editors are the files it reads: schema/platform_schema.json (which fields exist and how each is edited) and catalog/device_catalog.json (the known PCI device models), plus the wxWidgets runtime DLLs.

Note: The kit ships platedit_wx.exe and the launcher opens it (Devices > Open in PlatEd, or Configure in the bottom bar). The earlier Qt edition, platedit_qt.exe, is installed beside it and is used only if the wx edition is missing.

 

What it needs

Item

Why

Where the editor looks

schema/ and catalog/

Field rules and device models.

PLATEDIT_DATA_DIR if set; else the folder of platedit_wx.exe; else the source tree (developer builds).

disk_types.json

The drive models the emulator supports; the Configure wizard offers these.

PLATEDIT_DISK_TYPES if set; else config/disk_types.json beside, one level above, or two levels above the data folder. In an installed or run directory this is <run-dir>/config/disk_types.json.

Emulatr.ini

The board view's CPUs and memory ([System]) and the Configure wizard's disk folder ([Storage] diskDir). An empty or relative diskDir is resolved as the emulator resolves it: against the directory the emulator runs in (the ini's folder, or its parent when the ini is in a config folder).

The --ini the launcher passes (the system's own ini); else Emulatr.ini or config/Emulatr.ini beside the manifest; else <run-dir>/config/Emulatr.ini.

Write access

Saving a manifest writes the file and a .bak beside it; the wizard creates disk images in the disk folder.

The manifest folder and the disk folder.

No other service or connection is needed. The editor does not start the emulator and does not need it running. Do not edit a manifest that a running EMulatR instance is using; the emulator reads it only at start-up, so changes take effect at the next start.

 

Launching it

•Double-click platedit_wx.exe, then use File > Open... or File > Open Folder....

•Or give a manifest on the command line:

editors/platedit_wx.exe ds20_v7_3_platform.json

 

The launcher starts it with the system's own ini as well:

editors/platedit_wx.exe --ini <run-dir>/Emulatr.ini <run-dir>/ds20_v7_3_platform.json

The last folder used is remembered for the next start.

 

Headless self-test

--selftest loads a manifest without showing a window, prints the top of its device tree and the number of findings, and exits 0 on success or 1 if the file cannot be loaded. It is used by build checks:

editors/platedit_wx.exe --selftest ds20_v7_3_platform.json

--export-diagram writes the board view of a manifest to a PNG without showing a window (reading the Emulatr.ini found beside the manifest or in the run directory), and exits 0 on success or 1 on failure:

editors/platedit_wx.exe --export-diagram ds20_v7_3_platform.json ds20_diagram.png

 

Environment variables

Variable

Effect

PLATEDIT_DATA_DIR

Folder holding schema/ and catalog/.

PLATEDIT_DISK_TYPES

Full path of the drive table (disk_types.json).

EMulatR_DISK_DIR

First choice for the Configure wizard's disk folder (the same variable the emulator uses).

EMulatR_NET_ADAPTER

Shown on the wizard's Network page as this host's network binding. The editor does not change it.
