Installing with the Windows Installer

Beta and release builds of EmulatR are distributed as a single Windows setup program (EmulatR_V<version>-setup.exe). The installer places a complete, ready-to-run installation under:

 

C:\Program Files\eNVy Systems, Inc\ASA-EmulatR

 

No source tree, compiler, or Qt installation is required -- the installer carries everything the applications need. Building from source remains available for developers and is described in Building from Source.

 

Upgrading or reinstalling: uninstall first

Before installing a new build over an existing installation, uninstall the existing one first: open Windows Settings, then Apps, then Installed apps (on older Windows: Control Panel, Add/Remove Programs), locate ASA EmulatR, and choose Uninstall. Then run the new installer.

 

This is the recommended upgrade path for every new build. Installing on top of an existing installation can leave files from the previous version behind, and Windows loads DLLs from the application directory before anywhere else -- a stale library alongside a new executable can cause startup failures that look like a broken build. A clean uninstall/install guarantees the installation directory contains exactly one consistent version.

 

Uninstalling does not touch your data. Named-system definitions, run directories, disk images, and logs all live outside the installation directory and are preserved across uninstall/reinstall cycles. The one exception to check: if you copied SRM firmware images into the installation's firmware\ folder, keep a copy elsewhere before uninstalling.

 

What the installer delivers

Component

Purpose

Emulatr.exe

The emulator itself, with its config\ data and the platform manifests.

EmulatrLaunch.exe

The launcher -- the recommended front door. It creates and manages named systems, run directories, and disk images, and starts the emulator for you.

editors\platedit_qt.exe

The Platform Editor for authoring and validating platform manifests.

firmware\

Intentionally empty. SRM console images are licensed material and are not distributed; you supply your own. See Firmware Requirements.

tools\

A small set of helper utilities (disk image creation, console driver, disassembler). The Python scripts require a Python 3 installation.

 

After installing

1. Copy your SRM firmware image(s) into the installation's firmware\ folder.

2. Start EmulatrLaunch.exe and create a named system -- the launcher builds the run directory, disk images, and configuration for you.

3. Boot, and connect to the console. See First Startup.

 

Before the first run: exclude EmulatR's folders from antivirus scanning, and keep run directories out of cloud-synced folders such as OneDrive. See Antivirus and Cloud Sync.
