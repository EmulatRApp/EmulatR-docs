v2.0

EmulatR V2.0 is the first release of the 2.0 line. The headline over X1.6-15: cold boots are dramatically faster, the machine's settings finally persist the way real hardware's do, and OpenVMS distribution media boots from the CD-ROM drive -- the beginning of the path to installing an operating system entirely inside EmulatR.

 

Performance

•Block execution is now the normal execution model. Straight-line instruction runs execute from a decoded block cache with device interrupts still delivered at one-instruction latency. A DS10 cold boot to the OpenVMS Username: prompt dropped from ~77 minutes to ~29 minutes; a DS20 boot-to-startup-complete measures ~34 minutes. The depth dial (EMULATR_BLOCK_MAX) now safely reaches 256. Block-Execution

•The interval timer is edge-exact at any block depth. A timer boundary that falls inside a block can no longer be stepped over -- the class of stall this once caused (depth-32 boots hanging at TDF) is structurally gone.

•Calibrated firmware delays are collapsed, always. The delay census that discovers them ships on and costs one performance tax on first execution; every later boot consumes what was discovered.

•The console MHz badge is honest. The SRM banner now shows the prior run's measured effective speed, marked ~ as historical (e.g. AlphaServer DS20 ~13 MHz), instead of a misleadingly low early-boot average. First-ever boots keep the live figure.

 

Storage

•SCSI CD-ROM device type (scsi_cdrom). An ISO can now be hosted on the SCSI bus (DKA400-style), where the SRM enumerates it as an RRD46-class drive.

•One drive catalog. The drive-profile table the emulator enforces is now generated from config/disk_types.json -- the same catalog the launcher's Make Disk uses -- so a disk the launcher creates is always a disk the emulator attaches. (Previously the two could disagree; a Make-Disk image could be refused at attach.)

•Storage attach failures are unmissable. A manifest row that cannot attach (unknown model, undersized image) now prints a loud banner naming the guest device that will be missing, plus an end-of-attach summary -- no more silently absent boot disks.

 

Machine state / operation

•NVRAM behaves like real hardware. The flash NVRAM (<firmware>.rom -- SRM environment variables, TOY) is created and maintained exclusively by the running instance: set at the console, clean shutdown, and the setting is there on the next boot. No tool or script touches these files any more, and they are never shipped -- a fresh install builds its own from factory state.

•Named run environments. tools/emulatr_env.sh gives each platform (ds10/ds20/ds20b/es40/es40b) an isolated console port, storage set, NVRAM, and run directory, so concurrent manual machines cannot disturb each other.

•Interactive firmware update. EMULATR_LFU_INTERACTIVE=1 hands the LFU's prompts to the operator (the auto-responder otherwise answers them, as in 1.6-15). The default, the EmulatR UART console asserts <enter><exit> automatically.  This is to ensure the SRM fidelity path is fully executed.

 

Fidelity

•CD-ROM boot from ATAPI (dqa1). The Cypress CY82C693 IDE function now presents its Interrupt Pin/Line registers per the CY82C693UB datasheet; the firmware routes the IDE interrupt (ISA IRQ14) exactly as real POST does, and OpenVMS's driver receives its interrupts. Previously a CD boot hung silently after the OpenVMS banner.

•Platform execution mode is manifest-bound. ES40/ES45 require the silicon path by manifest declaration; the environment cannot accidentally select the wrong mode, and the operator is warned loudly on any mismatch.

•PCI I/O window widened to the HRM's 32MB; DS10 on-board INTx routing corrected; ES40 south-bridge modelling advanced.

 

Diagnostics (diagnostic builds)

•PIC/IACK trace

•Cchip interrupt-delivery probe

•Unclaimed-port-I/O trace

•Full-width IDE taskfile trace

•Windowed rate sampler with live PC

•PC-gated instruction ring dumps

This is the instrument set that root-caused this release's fixes, retained for the field.

 

Data files (JSON) -- what V2.0 reads and writes

V2.0 formalizes a family of JSON data files. They divide cleanly into authored configuration (you may edit) and run products (the emulator writes them; treat like the flash NVRAM -- do not hand-edit or copy between machines).

 

Authored configuration (consumed):

•config/disk_types.json -- the storage device catalog, and new in V2.0 the single authored source for drive identity and geometry: the emulator's enforced drive-profile table is now generated from it (tools/gen_drive_profiles.py), and the launcher's Make Disk reads the same file. Add or change a drive here, regenerate, rebuild -- never by editing C++ tables. Admission is authority-gated: every populated field cites a document, a measured capture, or is declared synthetic; custom_drives is the hand-editable overlay.

•<platform>_platform.json -- the platform manifests. The copy in common/ is the manifest of record; run-dir copies are consumed and deliberately editable for experiments. V2.0 additions: the execution_mode binding (ES40/ES45 declare silicon; the environment cannot override) and the scsi_cdrom storage row type.

•config/env_registry.json (+ env_registry_release.json) -- generated capability declaration of every EMULATR_* runtime knob in the binary, consumed by the launcher's environment panel. Regenerate with tools/gen_env_registry.py; do not hand-edit.

 

Run products (created and consumed by the emulator, stem-keyed beside the firmware image):

•<firmware>_warp.json -- the calibrated-delay census (always on, no knob). The first boot of a firmware image generates it (a one-time discovery tax); every later boot consumes it. Content-bound to the exact image (FNV-1a hash + size): a census for different firmware bytes is refused loudly as stale and regenerated at clean exit.

•<firmware>_badge.json -- the console MHz badge figure from the prior clean run, bound to platform mode + block depth; a mismatch on either falls back to the live gauge. Host-specific by nature (it is a measurement of the machine EmulatR ran on).

•<firmware>_trcprofile.json -- trace-bench loop profile, consumed by diagnostic builds when present (pattern watch); same content-bound staleness rule as the warp census. Absent file = silence.

 

Two rules span all three run products (architect ruling 2026-08-27, matching the flash-NVRAM rule):

1.They never ship. Each is a product of the instance that runs -- and since the firmware images themselves are user-supplied and never packaged, an artifact keyed to unshipped bytes cannot be validated at package time. A fresh install generates its own on first boot.

2.They are stem-keyed to the --firmware image, loudly refuse staleness rather than silently misleading, and an absent file always degrades to first-boot behavior -- never to a half-configured state.

 

Networking (EWA0)

•The emulated DE500-BA reaches a real network. EWA0 bridges to a dedicated host adapter and the guest becomes an ordinary node on the LAN: it answers ARP, replies to ping, and accepts TELNET and FTP sessions. Verified end to end on a DS20 running OpenVMS V8.3, with the guest's own LANCP counters reconciling against the wire in both directions and every error counter at zero.

•On by default, by auto-detection. With nothing configured, EmulatR looks for a DEDICATED adapter -- one that is up, connected, and carries NO bound network address -- and attaches to it. That test cannot select the host's own NIC, because the host's adapter always carries an address. If no such adapter exists, or if several do, EmulatR reports what it found and continues with a fully working NIC and no wire attached. Set EMULATR_NET_ADAPTER to a device name or description substring to choose one, or to off to disable.

•Turn it off for any timing run. A live backend makes a run NON-DETERMINISTIC: inbound frames arrive on other machines' schedules, so two runs of the same workload no longer execute the same instruction stream. Determinism is a load-bearing property of this emulator, and networking is the one feature that breaks it by design.

•Layer 2 and protocol-agnostic -- what that does and does not promise. EmulatR does not inspect, translate or terminate guest traffic above the Ethernet header, so anything OpenVMS layers on Ethernet is carried unmodified. PROVEN ROUND-TRIP: TCP/IP and ARP. PROVEN OUTBOUND ONLY: DECnet Phase IV, DECnet-Plus/OSI (ES-IS), MOP and DTSS -- correctly formed on the wire, but nothing answered them, because the test LAN holds no other DECnet node, LAT service or InfoServer. CARRIED BUT UNTESTED: LAT, LAST/InfoServer, and the SCS traffic an OpenVMS Cluster runs on, and with SCS, MSCP serving between nodes -- zero frames of any of these have been observed.

•The receive path is proven for all three address classes. Unicast, broadcast and true multicast have each been delivered and consumed, and the 21143 address filter is implemented in all four of its modes (perfect, 512-bit hash, inverse, hash-only). That matters more than the protocol list above: the protocols still untested are almost all MULTICAST-addressed, so a defective receive filter would have failed every one of them while leaving ping and TELNET working normally.

•Cluster configurations are NOT claimed. The Layer 2 transport a VMScluster needs is present and proven in both directions, but clustering itself is UNTESTED. The open question is whether SCS tolerates an emulated node's timing, and the failure mode if it does not is a bugcheck rather than a graceful degradation. Do not plan a production cluster on this release.

•Requires Npcap; Wireshark is recommended. EmulatR loads wpcap.dll at run time and is never linked against it, so no SDK is needed. Npcap is bundled with Wireshark, which is the easiest way to obtain it -- and you will want Wireshark anyway, because EmulatR writes its packet captures in libpcap format. When installing Npcap, leave "Restrict Npcap driver's access to Administrators only" UNCHECKED, or EmulatR must be run elevated to open the adapter.

•Use a dedicated adapter, and provision it. A second NIC used for nothing else, with every protocol UNBOUND except the Npcap packet driver. Windows adapter defaults are wrong for this role -- leaving Energy Efficient Ethernet enabled is by itself enough to make bulk transfers fail in a way that looks like an emulator defect. tools\provision_enic.ps1 sets the properties that matter and saves the previous values so the change is reversible. RE-RUN IT AFTER ANY DRIVER UPDATE. A Wireshark configuration profile ships in tools\wireshark\.

 

Also fixed

•Closed in this release. The 21143's TX/RX descriptor DMA and its scatter-gather facility (the foundation the whole networking section above rests on), the ATAPI CD-boot stall, the TCP/IP STARTDROUT hang, console echo lag at the OpenVMS prompt, launcher generation of Emulatr.ini, the version-sync script reading the wrong CMakeLists.txt, and a missing diagnostic-gate include in the 16550 UART.

•Firmware UPDATE images are answered automatically. A DS20 firmware image such as ds20_v7_3.exe is the update DISTRIBUTION, not the resident console: its designed flow prompts for a console update and runs the LFU menu before chaining into the SRM. A real machine runs that image ONCE to program its flash and boots from flash forever after; EmulatR presents the image every cold boot, so the detour recurs. Rather than stall you at those prompts, EmulatR answers them and carries the boot through to the >>> prompt. Set EMULATR_LFU_INTERACTIVE to drive the LFU dialog yourself.

Known limitations

•The DE500 (tulip) NIC is not fully implemented: DECnet/TCP/IP startup phases carry timeouts against it.

•Bus-master (DMA) IDE is not modeled; all IDE/ATAPI transfer is PIO. The shipped firmware and OpenVMS boot path use PIO exclusively. (JRN-V2-BMIDE-001)

•The Cypress USB function is not modeled; the firmware's probe of it logs one recoverable PCI error line per bus reset. Harmless. (JRN-V2-PCICFG-001)

•Booting from a SCSI-hosted CD (b dka400) enumerates but does not yet boot -- see Storage above.

•ES40 remains pre-beta: the silicon path stalls in firmware initialization (under investigation, JRN-V2-PCICFG-001 / JRN-V2-ES40PCI trail).
