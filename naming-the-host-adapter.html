Naming the Host Adapter (EMULATR_NET_ADAPTER)

By default EmulatR chooses the host adapter for EWA0 by itself. This page covers everything needed to name one explicitly instead, using EMULATR_NET_ADAPTER -- from finding the adapter, through setting it in the Launcher, to confirming it took effect.

 

When you need to name an adapter

Situation

Why auto-detection does not do it

The run log says several adapters have no bound address

more than one adapter qualifies, and EmulatR will not guess between them

You are sharing an adapter with the host

auto-detection never selects an adapter that holds an address -- by design, so it can never take over the computer's own connection

You want a particular adapter

auto-detection picks by rule, not by preference

 

Otherwise leave it unset: auto-detection is the recommended arrangement. See Choosing the Host Adapter (Wi-Fi and Wired).

 

1. Find the adapter

 

In PowerShell:

Get-NetAdapter | Format-Table Name, InterfaceDescription, Status, MediaType

 

Choose the WIRED adapter -- MediaType 802.3. A Wi-Fi adapter (Native 802.11) cannot carry the guest, whatever you name.

Take a distinctive part of its InterfaceDescription. For Intel(R) Ethernet Connection (3) I219-LM, the value I219 is enough. Case does not matter, but the text must match ONE adapter only -- check it against the whole list.

 

2. Choose the value

Value

Example

Use it when

A description substring (recommended)

I219

almost always. It survives a device GUID change, which happens when hardware is moved or a driver is reinstalled

A device name

\Device\NPF_{DD1B82DC-0887-4F32-AD71-0D9CCE161C71}

only when two adapters share a description and no substring tells them apart

off, none or 0

off

to switch networking off for this system -- for example for a run you intend to time

(row unticked)

--

to return to auto-detection, the default

 

3. Set it in the Launcher

The Launcher is where this setting takes effect for an installed EmulatR. Set it there, for each named system that needs it.

 

1. Start the Launcher and select the named system.

2. On that system's details, find the group Run-time environment variables. Its columns are a tick box, Name, Value and Description.

3. Find the row EMULATR_NET_ADAPTER. It is shown without ticking Show developer variables.

4. Double-click its Value cell (or select it and press F2), type the value, and press Enter.

5. TICK THE BOX ON THAT ROW. This is the step that is easy to miss, and nothing warns you if you do.

 

An unticked row is ignored. The Launcher applies only ticked rows: a value typed into an unticked row is discarded, auto-detection runs instead, and the run looks exactly as if you had set nothing.

 

One setting per named system

The value and its tick box are saved with the named system. A second named system has its own row and needs setting separately -- which also means two systems can be bridged onto different adapters.

 

Not as a Windows environment variable

Setting EMULATR_NET_ADAPTER in Windows System Properties does not work with the Launcher. Whenever that row is unticked, the Launcher REMOVES the variable before starting the emulator, so that a value left behind from some earlier session cannot silently change a run. The Launcher's row is the only place to set it.

 

4. Confirm it took effect

Start the named system and check two things in its run log, in the system's logs folder.

 

First, that the Launcher applied your value. The run log's header lists every variable it set:

 EMULATR_* environment enabled for this run:

 EMULATR_NET_ADAPTER=I219

 

If instead it says EMULATR_* environment: none enabled for this run., the row was not ticked -- go back to step 3.

 

Second, that the emulator attached to the adapter you named:

EWA0 network backend ATTACHED to '\Device\NPF_{...}' ...

 

Then, from the guest, ping your gateway and another machine.

 

If it did not attach

The run log says

Meaning

Fix

EMULATR_* environment: none enabled for this run.

the row was not ticked, so your value was discarded

tick the box on the EMULATR_NET_ADAPTER row

EWA0 network backend UNAVAILABLE: no host interface matches '...'

nothing matched the text you typed

EmulatR lists every adapter it can see directly beneath this line -- pick a distinctive part of one of those

EWA0 network backend UNAVAILABLE: cannot open '...'

the adapter was found but could not be opened; usually Npcap was installed with "Restrict Npcap driver's access to Administrators only" ticked

reinstall Npcap with that option UNCHECKED, or run EmulatR as administrator

EWA0 network backend: no adapter attached -- ...

the variable was not set, so auto-detection ran and declined

set and TICK the row, as above

ATTACHED, but the guest reaches nothing

usually a Wi-Fi adapter was named, or the port has powered down

name a WIRED adapter, and re-run tools\provision_enic.ps1

 

A networking problem never stops EmulatR from starting: in every case above the guest keeps a working network adapter with no wire, and the run continues.

 

Networking makes a run NON-DETERMINISTIC -- frames arrive on other machines' schedules. Set the value to off for any run you intend to time or compare.
