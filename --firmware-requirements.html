Firmware Requirements

EmulatR requires an SRM console firmware image to execute. The DS10 reference image is an SRM V7.3 build (ds10_v7_3.exe).

 

The image is selected in precedence order:

--firmware <path> on the command line (overrides the ini for a single run); or

the [ROM]/firmwareImage ini key. There is no default - an empty value is a hard configuration error ("config invalid: ROM.firmwareImage is required but empty"), and both examples in the shipped ini are commented out, so a run must name an image one way or the other.

 

Path gotcha: the ini value is a PATH resolved against the current working directory, not against the installation - the shipped examples read firmware/ds10_v7_3.exe. Launch from the Emulatr root, or pass an explicit --firmware firmware/ds10_v7_3.exe.

Optional integrity check: set [ROM]/firmwareSha256 to verify the image at load. When empty, the integrity check is skipped.

 

Provenance and licensing

EmulatR does not distribute SRM firmware. The images are copyrighted DEC / Compaq / HP material and are not EmulatR's to ship, so a distribution kit contains an EMPTY firmware/ directory by policy and you supply your own image - typically from hardware you own or from a vendor archive you have the right to use.

 

Which SRM versions work

There is no version gate: EmulatR does not inspect or reject an image by SRM version, so any console image for a supported platform is worth trying. What is actually exercised is V7.3 - the reference images for DS10, DS20, DS25, ES40 and ES45 are all V7.3 builds, and that is what the platform work is verified against. Older images (a DS20L V6.6, for instance) load by the same path but are untested.

 

Both the compressed console image (.exe) and a pre-decompressed console image are accepted; the format is detected from the file, and a pre-decompressed image skips the guest self-decompression entirely. Mind the extension though: .rom is used for TWO different things. A file passed to --firmware with a .rom extension is loaded as a pre-decompressed console image, but <stem>.rom beside the firmware is the machine's flash/NVRAM backing file, bound automatically and never booted. See Firmware Images: .exe and .rom.
