Why a neutral machine

Several things in this kit have never run anywhere but the development host, where the answer was already present: firmware already existed, Npcap was already installed, Visual Studio supplied the C++ run time, and a dedicated network adapter was already provisioned. Each is a place where the kit consistently depends on something it does not ship.

 

Do not "fix" the machine to make a test pass. A tester's machine will not be fixed either. If a step needs something the kit did not provide, that is the finding — record it and continue.

Section 6 — Networking with Npcap

#

Step

Expected

Result

6.1

Install Wireshark (which bundles Npcap). Leave "Restrict Npcap driver's access to Administrators only" UNCHECKED

installed

6.2

In Network Connections (ncpa.cpl), open Properties on every adapter EXCEPT the dedicated EmulatR one, and uncheck Npcap Packet Driver (NPCAP)

Wireshark's installer enables Npcap on every adapter. Afterwords it should be enabled on the EmulatR adapter only

6.3

Open Properties on the dedicated EmulatR adapter

only Npcap Packet Driver (NPCAP) is checked — every other protocol, client, service and filter unchecked

6.4

Restart the emulator with no EMULATR_NET_ADAPTER set

auto-detect runs

6.5

Record the EWA0 back-end line verbatim

either attached to … or several adapters have no bound address … — see §K2

6.6

If auto-detect declined, note every adapter it listed

recorded

6.7

Run tools\provision_enic.ps1 against a spare adapter if the machine has one

reports what it changed and saved

6.8

Set EMULATR_NET_ADAPTER to that adapter and restart

EWA0 network backend ATTACHED to …

6.9

From the guest, ping the gateway and another host

replies

6.10

Check the guest's own counters (LANCP SHOW DEVICE EWA0/COUNTERS under OpenVMS)

no errors

6.11

Import tools\wireshark\EmulatR-EWA0.zip via Edit → Configuration Profiles → Import → from zip file

profile imports; filter buttons appear

6.12

Capture on the bridged adapter and apply the Undec button

ideally no frames — anything there is a model gap

To check every adapter at once, in PowerShell:Get-NetAdapterBinding | Where-Object ComponentID -like '*NPCAP*' | Format-Table Name, EnabledEnabled must be True for the EmulatR adapter and False for every other. The pattern matches either Npcap component ID, NPCAP or INSECURE_NPCAP, which differ depending on how Npcap was installed.

§K — Known gaps: expected, already recorded, do not file these

ID

What you will see

Status

K1 JRN-V2-LAUNCHVER-001

firmware_readme.txt ends with EmulatrLaunch 1.0.0-alpha … 2026-07-29 that does not match the installed kit's version

open; fix next release

K2 auto-detect

On a machine with WAN Miniport pseudo-adapters, auto-detect may list several candidates and decline to choose. Naming the adapter explicitly is the workaround

known; the live-wire filter permits "connection status unknown"

K3 JRN-V2-PKGLOGS-001

The package dialog says, in red, "Trace output was not included — it is far too large to send", and never says where to send the zip

open; to be replaced with a forwarding instruction next release

K4 ATAPI CD boot

Booting an ISO is slow, with long silent stretches

by design — the console's driver reads one sector per command packet

K5 guest date prompt

OpenVMS may ask for the date on a fresh TOY store

expected; one-time initialization, the battery-replacement equivalent

K6 guest reboot

If VMS asks to reboot, EmulatR halts cleanly instead of restarting itself

known limitation; restart and boot again
