Pipeline Machinery -- Bachman Diagram

This topic maps the pipeline machinery -- from instruction decode through block execution to interrupt delivery -- as a Bachman diagram. Boxes are record types. A labelled arrow is a set: it runs from the owner to the member and reads 1:N unless marked 1:1. Sets are named in lower case.

1. Layer map

The machinery separates into five layers. The diagram in section 2 is drawn in these bands.

 

Layer

Role

L1 -- Identity / Coherence

What makes a cached artifact still valid.

L2 -- Decode

The side-effect-free decode oracle.

L3 -- Block

Straight-line descriptor runs.

L4 -- Execute

The faithful back-end, replayed verbatim.

L5 -- Interrupt delivery

Assert -> detect -> accept -> divert.

 

L5 is the interrupt-delivery layer this topic exists to show explicitly -- it is the one layer that both reads from and writes into the execution layers below it.

        |---------------------------|   or once per retire on the

        | crossed-edge timer test   |

           *** THE BOUNDARY CHECK IS UNCONDITIONAL BY RULING. ***

           S-3b tried to gate it on pendingIrq1 and the gate was

           SELF-REFERENTIAL: pendingIrq1 reads (drir & dim), but the

           ISA DRIR bit is SET BY mirrorIsaIrqs() -- inside the very

           section being skipped.  Measured: %STDRV gap 174 s -> 502 s.

           Built and removed 2026-08-22.

 

        PATH 2 -- IN-LOOP BREAK-OUT (F-2)

 

        +---------------------------+

        |  BlockExecutor::execute   |

        |---------------------------|

        | if (i != 0 &&             |     two relaxed loads, two ANDs,

        |     (drir & dim & mask))  |     one predicted-not-taken branch

        |     return;               |

        +---------------------------+

                   ^        ^

                   |        | pushed once at construction by

                   |        | Machine (setIrqBreakSource) --

        g_irqBreakDrir       g_irqBreakDim / g_irqBreakMask

        (default: &g_irqBreakZero, so the loop needs NO null check;

         unpushed the test folds to false)

 

           i != 0 GUARANTEES FORWARD PROGRESS.  Without it, an interrupt

           the CPU cannot yet accept (IPL masked) breaks at i=0 forever:

           zero retires, livelock.  With it, the degenerate case is one

           retire per tryRun -- exactly the reference path's cost.

 

           This relocates DETECTION ONLY.  Delivery is still decided at

           the boundary.  Net: device-interrupt latency = ONE instruction

           at any block depth.

        | isum    <- EI[n] cause bit                    |

        |            EI[2]=1<<35 IRQ_CLK                |

           Reversed, the boot-to-SRM census measured 58,296,794 calls

           against 29,147,252 steps = 2.0001 per step.  Reordering

           REMOVES the calls rather than speeding them up.

4. The two invariants the diagram encodes

SDE invariant (no register residency). Descriptors carry {ge, encoded} only; every operand is read live from CpuState per grain. The executor holds no register residency, so the PAL shadow-bank swap cannot go stale across a boundary. Any future executor state that caches register content or pointers must be invalidated at PAL entry/exit boundaries. In Bachman terms: there is no set from Desc to any register record, and that absence is load-bearing.

No in-block invalidation check, by contract. Content coherency is IMB (CALL_PAL -- never inside a block, stop condition 3) and mapping changes are HW_MTPR (never inside a block, stop condition 4). No event that could invalidate a block can occur while it executes, so the generation check lives only at entry (hit()), not per instruction.

 

5. What is deliberately not in the diagram

•Link following. linkFall / linkTaken are filled at seal and never followed in the current component D. Chaining is a dispatch change on those slots, not a rewrite -- drawn as fields, not as sets.

•SMP fan-out. The dimWord(0) / pendingIrqN(0) hooks are hardcoded to CPU 0; uniprocessor is the shipping configuration and the per-CPU generalisation belongs to the SMP decision.

•The 8259 IMR/EOI edges and DIM writes, which remain unwired pending-ness edges (F-3).

•PALcode internals. PAL mode never enters a block, so L3/L4 simply do not apply inside PALcode.

 

6. Reading the diagram for performance work

Trace any proposed change through the layer it actually touches:

•Touching L3 depth (EMULATR_BLOCK_MAX) changes how often L5b Path 1 runs. It does not change L4 per-instruction cost. See Block-MAX-Internals.

•Touching L5b Path 1 (gating the boundary) is the S-3b trap: the predicate you would gate on is computed by the body you would skip.

•Touching L5c ordering is nearly free and was worth ~2 calls per step.

•Touching L4 changes real work and needs the retire-diff gate.
