The dedicated adapter with no IP address; the run log must show EWA0 network backend ATTACHED. On this host: Intel(R) Ethernet Connection (3) I219-LM.

The host itself, at 192.168.1.108 on the same LAN

system disk

OpenVMS

MC LANCP, then SET DEVICE and DEFINE DEVICE EWA0 /SPEED=100 /FULL_DUPLEX /NOAUTONEGOTIATE

TCP/IP

@SYS$MANAGER:TCPIP$CONFIG, with an address outside the router's DHCP range. The guide's plan uses 192.168.1.48 for the ES40.

DECnet

Give the environment its own address. The guide's ES40 value, 1.3, was read from the live ES40, and env-es40c is a clone of that disk. An address such as 1.5 avoids the MAC clash if both ever run networked at once.

Pass

N-1

Host ping 192.168.1.48; guest TCPIP PING 192.168.1.108

Replies both ways.

N-2

TELNET from the host into the guest

Username: over the network.

N-3

FTP a large file (about 50 MB) each way; compare checksums (CHECKSUM in OpenVMS, certutil -hashfile on the host)

Identical, at a steady rate. This also checks that the 20 September FTP slowdown does not return.

N-4

LANCP SHOW DEVICE EWA0/COUNTERS before and after

No errors beyond the one error count the DE500-BA driver always reports.

N-5

DECnet between env-es40c and a second EMulatR (a DS20 on its own address): SET HOST, DIR node::, COPY

Works. Whether Npcap passes one instance's frames to another on the same adapter is unverified, and part of what this tests.

N-6

Repeat N-1 to N-3 with EMulatR_IRQ_HARNESS=1 and the JIT on

Same results. Network interrupts are a harness path the boot tests never exercise.

Evidence: Wireshark on the host adapter, filtered on the guest's MAC address, or EMulatR_DIAG_TULIP_PCAP on the RelWithDebInfo build for frame-level captures of EWA0 itself.
