6.8 JIT (Just-in-Time Execution)

EMulatR can run frequently executed guest code through a JIT instead of the instruction-by-instruction interpreter. The fused JIT is on by default. It changes how the host executes guest instructions, never which instructions the guest executes: every JIT change is checked against the interpreter by a differential test harness, including fault cases, and by an unchanged boot milestone.

 

Turning it off

EMulatR_JIT=off

 

Set it in the environment before launching (EMulatR_JIT=0 is the same) to run the interpreter alone. Leaving EMulatR_JIT unset, or setting fused or 1, runs the JIT. EMulatR_NO_JIT forces the JIT off whatever else is set. Earlier builds had the JIT off unless it was asked for; a script that turned it off by leaving the variable unset must now set EMulatR_JIT=off. For the best speed, use the Release build.

 

What it does

•A block of guest instructions that has run EMulatR_JIT_HOT times (default 64) is compiled into a fused sequence of micro-operations that runs without per-instruction dispatch.

•Compiled directly: integer add, subtract and scaled add/subtract, logical operations, shifts, compares, LDA/LDAH, branches, and the loads and stores LDL, LDQ, LDQ_U (including the UNOP form), STL and STQ.

•Any other instruction in the block runs through the interpreter in place, and the block continues. When a compiled instruction meets a case it does not handle (a fault, a device access), it hands back to the interpreter at exactly that instruction.

•At most EMulatR_JIT_MAX_BLOCKS blocks (default 4096) are compiled.

 

Memory fast path

With the JIT on, ordinary loads and stores to RAM run inline instead of through the full memory path. Accesses to device space, and any access that would fault, still take the full path. EMulatR_JIT_NO_MEMFAST turns off only the fast path, for comparisons. It also turns itself off while a memory watch or probe setting is active, because those settings need to see every access.

 

When the JIT stays off

The JIT does not run while a per-instruction observer is armed: a trace, a value or PC gate, checkpoints, the UART trace marker, or an EMulatR_DIAG_* setting. A compiled block does not report each instruction to those observers, so running it would silently change what they record. The run log says which observer kept it off.

 

Reading the run log

At start-up, one line always says what the JIT is doing:

Line

Meaning

JIT: off (EMulatR_JIT=off)

EMulatR_JIT is set to off (or 0): the interpreter alone.

JIT: fused (default)

The JIT is on and EMulatR_JIT is not set. With EMulatR_JIT=fused (or 1) the line reads JIT: fused.

JIT: off (observer armed: <setting>)

An observer is armed; the setting is named.

JIT: off (EMulatR_NO_JIT)

Forced off.

JIT memfast: ON

The memory fast path is active.

JIT memfast: OFF (<reason>)

The fast path is off, and why.

At exit, a JIT: line gives the block and retire counts, including jitShare, the percentage of guest instructions the JIT retired; a JITMEM: line counts the loads and stores the fast path handled.

Planned: native code emission (COMJit, release 2.2)

The fused JIT above runs micro-operations; it does not generate host machine code. Release 2.2 adds COMJit, which emits host instructions directly. The design below describes that emitter; it is not in the current build.

 

5.8 Cross-Platform JIT Architecture & Stack Bifurcation

To support multi-architecture targets like macOS/Intel (x86_64) and macOS/ARM (Apple Silicon) alongside the existing Windows/Linux x64 targets, the uniform execution layer introduces a stack bifurcation phase. This guarantees that regardless of the host platform, every instruction executes through a uniform, compressed call stack interface while delegating ABI-specific register spilling and frame setup to the underlying emitter backend.

Key Architectural Provisions

Compressed Call Stack Interface:

By enforcing a uniform-depth and uniform-width slot design, the JIT minimizes frame bloat.

 

Local variable spills and temporary registers share a compressed layout relative to the dedicated base pointer (R11 on x64 or equivalent fixed context pointer on ARM), eliminating redundant frame-pointer setup overhead across basic blocks.

 

Cross-Platform Target Bifurcation:

macOS/Intel (System V AMD64 ABI): Replaces the Win64 32-byte shadow space requirement with System V register-passing conventions (using RDI, RSI, RDX, RCX, R8, R9) while preserving the exact same uniform instruction slots.

 

macOS/ARM (Apple Silicon / AAPCS64): Adapts the emission layer to translate the DEC Alpha stream into 64-bit ARM instructions, mapping scalar floating-point and memory formatting to ARM load/store pair instructions (LDP/STP) and vector registers (V0-V31).

 

Unified Scaffolding and Epoch Checks:

Epoch-based interrupt checks and memory trap handlers remain structural constants at the block boundary, ensuring deterministic bailout behavior whether running on an x86 workstation or an Apple Silicon host.
