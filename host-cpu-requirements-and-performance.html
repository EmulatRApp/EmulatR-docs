Host CPU Requirements and Performance

EMulatR runs on any x86-64 (AMD64) processor. How fast it runs depends partly on which instruction-set extensions the host CPU reports. On startup EMulatR detects these extensions and selects the matching code path for its native code generator. Every path produces bit-identical emulation results; only the speed differs.

This topic describes the performance tiers, how virtual machine settings can affect them, and how to confirm which tier your host is using.

Minimum Requirement

Any 64-bit x86 processor from Intel or AMD. No specific instruction-set extension is required. If an extension is not present, EMulatR uses a baseline code path that uses only the standard x86-64 instruction set.

Performance Tiers

EMulatR uses two extensions to speed up the shift, byte-extract, byte-insert and byte-mask operations that are common in Alpha code: BMI1 and BMI2 (Bit Manipulation Instruction sets 1 and 2).

Tier

Extensions reported

Typical processors

Full

BMI1 and BMI2

Intel Core and Xeon, Haswell (4th generation, 2013) and later. AMD Excavator (2015) and all Ryzen, Threadripper and EPYC (Zen) processors.

Partial

BMI1 only

AMD Piledriver and Steamroller (FX, A-series). No Intel processor reports this combination on bare hardware, but a virtual machine can.

Baseline

Neither

Intel Sandy Bridge, Ivy Bridge and older. Some Intel Pentium, Celeron and Atom models, including some of later generations. Older AMD processors. Virtual machines whose CPU features are masked (see below).

Intel hybrid processors (Alder Lake and later) report the same extensions on performance and efficiency cores, so EMulatR selects the same tier whichever core it runs on.

First- and second-generation Zen processors (Ryzen 1000 to 3000 series, EPYC 7001 and 7002) report BMI2, but execute two of its instructions, PDEP and PEXT, much more slowly than other processors. EMulatR detects these processors and avoids those two instructions on them. They otherwise run in the Full tier.

Virtual Machine Hosts

When EMulatR runs inside a virtual machine, it sees the CPU features the hypervisor presents, not those of the physical processor. Features that let VMs move between hosts of different generations work by hiding newer extensions:

- VMware vSphere Enhanced vMotion Compatibility (EVC)

- Microsoft Hyper-V processor compatibility mode

- Similar CPU-model or baseline settings in KVM, Proxmox and other hypervisors

A current Intel Xeon or AMD EPYC host in a cluster whose baseline is set below Haswell (for example Sandy Bridge or Ivy Bridge) presents no BMI extensions, so EMulatR runs in the Baseline tier. EMulatR still runs correctly, just more slowly.

Recommendation: for virtual machines that host EMulatR, use a CPU baseline of Intel Haswell or later, or AMD Zen or later, where your cluster allows it. In Hyper-V, leave processor compatibility mode off for these VMs unless you need to live-migrate them between hosts of different generations.

Confirming Your Tier

EMulatR writes the detected host CPU features and the selected tier to the run log when it starts. The run log is in the logs subdirectory of the run directory. Look for a line of this form:

>>> EDITORIAL PLACEHOLDER: exact startup log line, e.g. HOSTCPU: vendor=GenuineIntel bmi1=1 bmi2=1 tier=Full overrides=none <<<

If you report a performance problem, include this line, and say whether EMulatR is running on bare hardware or in a virtual machine.

Diagnostic Overrides

For support and testing, EMulatR can be forced to a lower tier with environment variables. These are diagnostic tools, not tuning settings: they never make EMulatR faster.

Variable

Effect

EMulatR_NO_BMI2=1

Do not use BMI2 even if the host reports it (forces Partial, or Baseline if BMI1 is also absent).

EMulatR_NO_BMI1=1

Do not use BMI1 even if the host reports it. Set both variables to force Baseline.
