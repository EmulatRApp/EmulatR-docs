Antivirus and Cloud Sync

A running EmulatR system writes continuously to its run directory: disk images of several gigabytes, snapshots, NVRAM, logs and traces. Real-time antivirus scanners and cloud-sync clients both watch folders like this, and both can interfere with it. Set up the exclusions on this page BEFORE the first run.

 

What goes wrong without exclusions

Symptom

Cause

Guest disk access crawls; boots and installs take far longer than they should

the scanner re-reads a multi-gigabyte disk image after the guest writes to it

A write to a disk image fails, or the image is left inconsistent

a scanner or sync client has the file open at the moment the guest writes to it

Emulatr.exe will not start, or disappears after installation

the scanner quarantined it -- an unsigned beta program that emulates a CPU can trip heuristic detection

Heavy, continuous upload traffic

the run directory sits in a cloud-synced folder, and every change to a disk image is uploaded again

The run directories

%USERPROFILE%\Documents\EmulatR - or the directory into which EmulatR launcher created the environment.

the parent of every named system: disk images, snapshots, NVRAM, logs and traces

Disk images, if you moved them

wherever EMULATR_DISK_DIR points

only if you keep disk images outside the run directory

Emulatr.exe

Exclude folders, not your whole Documents folder and never a whole drive -- see The trade-off, below.

 

Microsoft Defender

Using Windows Security

Open Windows Security, then Virus & threat protection > Manage settings > Exclusions > Add or remove exclusions > Add an exclusion > Folder, and add each folder from the table above.

 

Using PowerShell

In an ELEVATED PowerShell (Run as administrator):

Add-MpPreference -ExclusionPath "$env:ProgramFiles\ASA-EmulatR"

Add-MpPreference -ExclusionPath (Join-Path ([Environment]::GetFolderPath("MyDocuments")) "EmulatR")

Add-MpPreference -ExclusionProcess "Emulatr.exe"

 

The second line asks Windows where your Documents folder really is, rather than assuming %USERPROFILE%\Documents. If Documents has been redirected -- to OneDrive, for example -- that is the path that matters.

To check what is excluded:

(Get-MpPreference).ExclusionPath

 

Other antivirus products

Exclude the same folders, and optionally the process, using your product's exclusion or allow-list settings; the wording varies by vendor. On a work computer, endpoint protection is often managed centrally and your own changes may be overridden -- ask your IT department to add the exclusions.

 

Cloud sync: OneDrive, Dropbox and similar

On many Windows computers the Documents folder is synchronised to OneDrive. New named systems are created under Documents by default, so on those computers every disk image is uploaded, re-uploaded on every change, and locked by the sync client while it does so.

To see where your Documents folder really is:

[Environment]::GetFolderPath("MyDocuments")

 

If the path contains OneDrive -- or the folder of another sync client -- choose a different location when you create a named system. The New System dialog pre-fills the Documents location; use Browse... to pick a folder outside any synced area, for example C:\EmulatR.

Keeping run directories out of synced folders is simpler and more reliable than excluding them from sync, which every client does differently. It also avoids OneDrive Files On-Demand, which can move a disk image to the cloud and leave only a placeholder that the emulator cannot read until it has downloaded again.

Exclude the new location from antivirus scanning as well.

 

The trade-off

An exclusion means files in that location are not scanned. Keep exclusions narrow -- EmulatR's own folders only -- and keep in them only firmware, disk images and ISO files from sources you trust, because nothing will check them there.
