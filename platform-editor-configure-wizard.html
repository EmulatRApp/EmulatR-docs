The Configure Wizard

Tools > Configure... (Ctrl+K, or the Configure... button) adds disks, a CD-ROM and a MAC address to the open manifest in one pass. It asks plain questions, works out every address and value from the same rules the rest of the editor uses, shows the whole plan, and changes nothing until you press Finish.

 

The wizard only adds. It never removes or changes an existing device; do that in the tree.

 

Page 1 -- Disks

Shows the platform, how many disks and CD-ROMs the manifest has now, and each storage controller with its free units, for example pka_53c810 (SCSI): full; cypress_ide (IDE): 3 free; cypress_ide2 (IDE): 4 free. Enter the total number of disks the system should have. The number cannot go below the current count, or above the current count plus every free unit.

Note: The emulator supports one SCSI controller and one IDE pair, so a system cannot have more disks than those controllers' free units. Adding controllers needs multi-controller support in the emulator.

 

Page 2 -- New disks

One row per new disk:

Column

Meaning

Bus

The controller. Defaults to the first bus with room, SCSI before IDE; you can change it.

Drive model

From disk_types.json: SCSI disks offer EMulatR-512M, EMulatR-4G, RZ28L and RZ29L; IDE disks offer EMulatR-ATA. The model sets the disk the guest sees and the image size. RZ40 is not offered: its size is not a whole number of 4 KB pages, which the storage pool needs.

Image file

The file name. The ... button picks an existing image (and clears New).

New

Ticked: the image is created when you press Finish. Unticked: an existing image is used.

Size (MB)

Only for a new EMulatR-ATA image, whose size is not fixed by the model.

Above the rows is the Disk folder: where new images are created. It starts from EMulatR_DISK_DIR, else the [Storage] diskDir of the system's Emulatr.ini (the one the launcher passes, or one beside the manifest or in the run directory; an empty or relative diskDir means the directory the emulator runs in), else the last folder used. The manifest keeps only the file name, so a run must use this folder as its disk directory.

 

Page 3 -- CD-ROM

If the manifest already has a CD-ROM, the page shows where it is and which ISO it uses, and there is nothing to add; change its ISO in the tree, or use + Device for a second drive. Otherwise tick Use a CD-ROM and choose an ISO file. The CD-ROM goes on IDE when a unit is free, otherwise on SCSI.

 

Page 4 -- Tape

Virtual tape is not yet supported; no tape drives are created. The page lists any tape rows the manifest has so you can remove them (the emulator cannot use them -- see V-45).

 

Page 5 -- Network

Shows the network controller: its slot, its interrupt route (from the same table the emulator uses) and its MAC address. The emulator supports one network controller, so there is nothing to count. This host's network binding (EMulatR_NET_ADAPTER, or auto-detect) is shown for information; it is a host setting, not part of the manifest.

 

A controller without a MAC in the manifest uses the built-in 08-00-2B-E5-40-00, which every such system shares; two of them on the same network would collide. The box Give ... its own MAC address (ticked by default) adds a random, locally administered address that no other manifest in the folder uses. A MAC can be changed later in the tree; 08-00-2B-... values are allowed there.

 

Page 6 -- Summary

Lists everything Finish will do: SET lines for MAC addresses, ADD lines for each disk and CD-ROM with its controller and address, the images to create with their full paths and sizes, and notes. Anything that would stop the plan is listed as BLOCKED or ERROR, and Finish stays disabled until you go Back and fix it -- for example an image name that already exists, no disk folder, not enough free space, or a change that would break a validation rule.

 

What Finish does

1.Checks the names and the free space for every new image.

2.Creates all the new images. Each is sized to the drive model, rounded up to whole 4 KB pages, and reads back as zeros; creation is instant and uses no disk space until the guest writes.

3.Only then adds the rows and MAC addresses to the manifest.

If anything fails, no row is added, and the message lists any images already created (they are left in place). The manifest is not saved automatically: use File > Save.

 

Undo

Edit > Undo Configure returns the manifest to how it was before Finish, as long as you have made no other edit since. It never deletes image files.
