12. Test/Regression

This chapter is the regression suite for the three supported platforms: how each test environment is set up, what is run, and what counts as a pass. Run it on every build that changes execution, interrupts, devices or the console, and record the results on a dated results page.

 

The environments

Each test runs in a named environment with its own console port, disk set and run directory, so the three platforms can be tested at the same time. Environments are created and launched with v3.0/tools/EMulatR_env.sh.

Golden disks

Every boot test starts from the same disks. Before each run the two disks OpenVMS writes (dka0.vdisk and dka200_vms83.vdisk) are copied from the environment's golden set and checked against its SHA-256 list. A golden set is taken only from disks that were shut down cleanly (the emulator writes a disk file only when it exits).

The four boot tests

Each platform runs the same four boot tests: the interrupt harness (EMulatR_IRQ_HARNESS) off and on, and the JIT (EMulatR_JIT) off and on. Every start is a cold boot. The earlier tests B-5 to B-8, which took a snapshot at the start of OpenVMS startup, were retired in 3.0 when snapshots were removed.

What a pass means

•OpenVMS startup completes: the STARTUP job reports job terminated at.

•After a Return at the console, OpenVMS prints the Username: prompt.

•No bugcheck, and no halt at the console.

The DS20 has one more condition, the reference count; see the DS20 page.

 

The console during a test

The SRM console accepts one connection at a time. A console may connect at any point in a run and receives everything printed before and after it connects. Builds before 3 October 2026 did not: a console that connected after the machine had printed with no console attached received nothing at all, which was the cause of the reports that a DS10 console reconnecting after an update restart, and a DS20 console connecting after startup, saw no output. The DS10 and ES40 tests keep one driver session from launch to Username:; the DS20 test stays unconnected until startup ends, so that its instruction count cannot be affected (see the DS20 page), and connects afterwards.

OpenVMS prints Username: only after a Return. A console that shows nothing after startup is idle, not stalled.

 

Stopping a run

Create EMulatR_STOP in the run directory. The emulator saves the flash and exits cleanly, and writes the disk files. The exit line reads Stop reason: StopRequested.

touch /d/EMulatR/project/out/build/v2.1-relwithdebinfo/env-ds10x/EMulatR_STOP

Do not use the SRM init command between tests. It does not reset the emulated machine, and a boot after it can halt with kernel stack not valid. Stop the emulator and start it again instead.

 

Other tests in every regression

•The unit suite: EMulatR_tests.exe in the run directory. All test cases must pass.

•The Platform Editor tests: ctest -R platedit in the build directory.
