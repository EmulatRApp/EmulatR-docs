Wireshark and Packet Captures

Wireshark is the tool for seeing what the emulated DE500 adapter (EWA0) actually puts on the wire and takes off it. This page covers the two ways to capture EWA0 traffic, how to find the guest's MAC address, the Wireshark profile EMulatR supplies, and filter examples for watching one machine or one protocol.

Installing Wireshark and Npcap, and preparing the host adapter, are covered on 5.9 Networking (EWA0).

 

Two ways to capture

EMulatR's own capture

Live capture on the host adapter

How

Start EMulatR with EMulatR_DIAG_TULIP_PCAP=1.

Start a capture in Wireshark on the host adapter EWA0 is bridged to.

Builds

Diagnostic (RelWithDebInfo) builds only.

Any build, including the installed kit.

Point of view

The guest's: every frame the guest transmits and every frame delivered to it.

The host adapter's: everything on that wire, including frames the guest never receives.

File

logs\<stem>_ewa0.pcap in the run directory.

Wherever Wireshark saves it.

Best for

What the guest really sent or received.

Confirming frames left the machine, and seeing other stations' replies.

 

Notes on EMulatR's own capture:

•The stem is the firmware name, for example ds20_v7_3_ewa0.pcap. The file has no timestamp, so the next run with the same stem overwrites it. Set EMulatR_LOG_STEM to a new name to keep a capture.

•Setup frames (the frames in which the operating system programs the adapter's address filter) never reach the wire, so they are not in the capture. EMulatR_DIAG_TULIP_DUMP=1 writes every transmitted, received and setup frame as a decoded hex dump to logs\de500dump_<date>_<time>.log.

•The capture has no frame check sequence. Leave Wireshark's Edit -> Preferences -> Protocols -> Ethernet -> Assume packets have FCS at Never (the default); Always removes four bytes of real data from every frame.

 

Finding the guest's MAC address

Every EMulatR EWA0 starts with the same hardware address, 08-00-2B-E5-40-00: the Digital prefix 08-00-2B, then E5-40, then the adapter number (00 for EWA0). It is fixed; there is no setting for it. The EMulatR run log does not print it. There are four places to read it.

 

At the SRM console

show device lists EWA0 with its hardware address:

>>>show device

ewa0.0.0.11.0 EWA0 08-00-2B-E5-40-00

The slot number in the device name differs by model (for example ewa0.0.0.4.0 on the ES40, whose prompt is P00>>>).

 

In OpenVMS

LANCP shows both the hardware address and the address the adapter is using now:

$ MC LANCP SHOW DEVICE EWA0 /CHARACTERISTICS

 08-00-2B-E5-40-00 Default MAC address (Hardware LAN address)

 AA-00-04-00-03-04 MAC address (Current LAN address)

Watch the current address: that is the one on the wire.

 

After DECnet Phase IV starts

DECnet Phase IV replaces the current address with one built from the node's DECnet address: AA-00-04-00-xx-yy. To work it out from a node address, compute area x 1024 + node, write it as four hexadecimal digits, and put the low byte first:

Guests that do not run DECnet Phase IV keep 08-00-2B-E5-40-00, so two of them on one LAN have the same address. Only one such guest may be on a LAN at a time.

 

In a capture

Wireshark shows Digital addresses with a vendor name in place of the prefix: 08:00:2b:e5:40:00 appears as DigitalEquip_e5:40:00, and aa:00:04:00:03:04 as DigitalEquip_00:03:04. Statistics -> Endpoints -> Ethernet lists every address in the file with its frame counts; the guest is the Digital address with transmitted frames. To see raw addresses instead of names, clear View -> Name Resolution -> Resolve Physical Addresses.

Filters take the address with colons (08:00:2b:e5:40:00); dashes, as OpenVMS and the console print it, also work in a single comparison.

 

The supplied Wireshark profile

EMulatR ships a Wireshark configuration profile, EMulatR-EWA0, that turns a raw capture into something readable. It is in the installed tree at tools\wireshark\ as both a folder and a zip, and provides three things:

File

What it gives you

dfilters

A grouped bookmark list beside the display filter bar: ANOMALIES, ADDRESSING, PROTOCOL FAMILIES and SANITY.

dfilter_buttons

One-click toolbar buttons: All, Bcast, Mcast, Group, Unicast!, DECnet, OSI, IP, Undec, <60, >1514.

colorfilters

Coloring rules, first match wins. Defects are loud; protocol families are light backgrounds meant for reading.

 

To install it: Edit -> Configuration Profiles -> Import -> from zip file, choose EMulatR-EWA0.zip, then select EMulatR-EWA0 from the profile list (it also appears in the bottom-right corner of the status bar). If the import misbehaves, copy the EMulatR-EWA0 folder into %APPDATA%\Wireshark\profiles\ instead and restart Wireshark.

 

The bookmark list and toolbar buttons appear only once a capture file is open. On Wireshark's welcome screen the only filter box is the CAPTURE filter, which takes a different syntax (see Capture filter examples below) and rejects display filters such as eth.dst. Open the file first.

The anomaly probes are the point of the profile. On a healthy capture each of these should find nothing:

Probe

A hit means

<60

A frame below the 60-byte minimum: a transmit padding defect in the model.

>1514

An oversize frame: a descriptor gather defect.

Unicast!

Unicast traffic. Normal once the guest has peers on the LAN; worth a look before that.

Undec

Nothing decoded the frame. This is where a genuine model gap would show, and also where MOP frames land (Wireshark has no MOP decoder).

 

Display filter examples

Type these into the display filter bar of an open capture. The examples use the default hardware address 08:00:2b:e5:40:00, the DECnet address aa:00:04:00:03:04 (node 1.3) and the guest IP address 192.168.1.48; replace them with your own. Every expression here was checked against Wireshark 4.6.8.

A list inside braces needs commas between its entries: {08:00:2b:e5:40:00, aa:00:04:00:03:04}.

Watching one guest

Filter

Shows

eth.addr == 08:00:2b:e5:40:00

Every frame to or from the guest's hardware address.

eth.addr in {08:00:2b:e5:40:00, aa:00:04:00:03:04}

The guest under either address: before and after DECnet Phase IV starts.

eth.src in {08:00:2b:e5:40:00, aa:00:04:00:03:04}

Only what the guest sent.

eth.dst in {08:00:2b:e5:40:00, aa:00:04:00:03:04} || eth.dst.ig == 1

Everything the guest can receive: frames addressed to it, plus broadcast and multicast.

eth.src[0:5] == 08:00:2b:e5:40

Any EMulatR adapter still on its default address. More than one source here means duplicate addresses on the LAN.

eth.src[0:4] == aa:00:04:00

Every DECnet Phase IV node on the LAN.

eth.addr == 08:00:2b:e5:40:00 && !arp && !ip

The guest's non-IP traffic only.

 

DEC protocols

Filter

Shows

dec_dna

DECnet Phase IV routing traffic (the same as eth.type == 0x6003).

eth.dst == ab:00:00:04:00:00

DECnet Phase IV router hellos, sent to all end nodes.

eth.dst == ab:00:00:03:00:00

DECnet Phase IV end-node hellos, sent to all routers.

clnp || esis || isis

DECnet-Plus (OSI) traffic.

lat

LAT terminal traffic (eth.type == 0x6004).

eth.dst == 09:00:2b:00:00:0f

LAT service announcements.

eth.type == 0x6007

OpenVMS Cluster (SCS) traffic over the LAN.

eth.dst[0:4] == ab:00:04:01

OpenVMS Cluster hello multicasts.

eth.type == 0x6001 || eth.type == 0x6002

MOP dump/load and MOP remote console. Wireshark has no MOP decoder, so match by type.

eth.type == 0x9000

Ethernet loopback test frames (Wireshark shows them as LOOP). In the captures seen so far, OpenVMS sends a few from its hardware address to its own DECnet address.

 

TCP/IP

Filter

Shows

ip.addr == 192.168.1.48

All IP traffic to or from the guest.

arp.src.proto_ipv4 == 192.168.1.48 || arp.dst.proto_ipv4 == 192.168.1.48

ARP about the guest's address: the first thing to check when ping fails.

icmp && ip.addr == 192.168.1.48

Ping requests and replies.

tcp.port == 23 && ip.addr == 192.168.1.48

Telnet sessions to the guest.

tcp.port == 22

SSH.

tcp.port == 21 || tcp.port == 20

FTP control and data.

udp.port == 123

NTP time synchronization.

 

Troubleshooting

Filter

Shows

tcp.flags.reset == 1

Refused or aborted TCP connections.

tcp.analysis.retransmission

TCP retransmissions: lost or late frames.

eth.addr[0:3] == 08:00:2b || eth.addr[0:3] == aa:00:04 || eth.addr[0:3] == ab:00:00 || eth.addr[0:3] == 09:00:2b

All Digital-related traffic: hardware and DECnet addresses and the DEC multicast blocks.

!(eth.type >= 0x6000 && eth.type <= 0x6009) && !(eth.addr[0:3] == 08:00:2b)

Everything that is NOT DEC traffic: the rest of the LAN, to rule it in or out.

 

For syntax that is guaranteed right for your Wireshark version, let Wireshark write it: click a frame, expand Ethernet II in the details pane, right-click a field and choose Apply as Filter -> Selected.

 

Capture filter examples

A live capture can be limited before it starts, so the file holds only what matters. These go in the capture filter box on Wireshark's welcome screen (or Capture -> Options). Capture filters use a different syntax from display filters.

Capture filter

Captures

ether host 08:00:2b:e5:40:00

Frames to or from the guest's hardware address.

ether host 08:00:2b:e5:40:00 or ether host aa:00:04:00:03:04

The guest under either address.

ether src 08:00:2b:e5:40:00

Only what the guest sends under its hardware address.

ether proto 0x6003

DECnet Phase IV.

ether proto 0x6004

LAT.

ether proto 0x6007

OpenVMS Cluster (SCS).

ether proto 0x6001 or ether proto 0x6002

MOP.

ether multicast

Broadcast and multicast only.

host 192.168.1.48

IP traffic to or from the guest.

not ip and not ip6 and not arp

Everything except TCP/IP: DEC protocols and other non-IP traffic.

 

Reading a capture

•The guest's periodic traffic is sparse. The guest clock runs slower than real time by design, so a DECnet hello that a real AlphaServer sends every 15 seconds appears only every several minutes from an EMulatR guest.

•In EMulatR's own capture, the frames from other stations are the ones the adapter delivered to the guest, so they show what the guest actually saw.

•If DECnet Phase IV is running but the guest still transmits from 08:00:2b:e5:40:00, the address change did not take effect. Check the setup frame in the EMulatR_DIAG_TULIP_DUMP output.
