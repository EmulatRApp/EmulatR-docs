Console Control Keys

The console is a serial line (COM1) that EMulatR carries over TCP to your terminal client. Control keys typed there travel down that line like any other character. Four of them matter when operating EMulatR: two belong to the operating system, and two are EMulatR's own diagnostic keys.

Key

Byte

Handled by

What it does

Ctrl/P

0x10

The guest (OpenVMS and the SRM console)

With OpenVMS running: halts the CPU and returns to the SRM console, which reports the halt and shows P00>>>. From there crash forces a crash dump, and continue resumes the system. See OpenVMS Crash or Hang: Capturing Diagnostics.

Ctrl/T

0x14

The guest (OpenVMS)

At a DCL session with SET CONTROL=T in effect: prints a one-line status of the current process (node, time, process name, CPU time, page faults, I/O, memory). Useful to see whether a long command is still working.

Ctrl/\

0x1C

EMulatR (diagnostic builds with EMulatR_DIAG_TRACE_HOTKEY=1); otherwise the guest

Starts the full instruction trace at the next instruction. See Console Trace Hotkey.

Ctrl/]

0x1D

EMulatR (diagnostic builds with EMulatR_DIAG_TRACE_HOTKEY=1); otherwise the guest

Stops the trace started with Ctrl/\. See Console Trace Hotkey.

Ctrl/P: halting OpenVMS

Ctrl/P is the operator halt. EMulatR passes it to the guest unchanged; OpenVMS and the SRM console do the rest, as on the real machine. After the halt the machine sits at P00>>>:

Type at P00>>>

Result

crash

OpenVMS writes a crash dump and reboots (if the system is set to). Set up the dump first -- see OpenVMS Crash or Hang.

continue

OpenVMS carries on from where it was halted.

b (boot)

Not recommended today: a warm boot after a halt faults the second boot (JRN-KSNV-001). Exit EMulatR and start it again for a fresh boot. See System Disk Configuration.

Note: A run with guest delay-loop warp on (EMulatR_UDELAYWARP) can be slow to answer Ctrl/P. If the halt does not appear, wait a few seconds before pressing it again.

 

Ctrl/T: process status

Ctrl/T is an OpenVMS terminal feature, off until enabled with SET CONTROL=T (put it in LOGIN.COM to have it always). The time it prints is the guest's clock, which runs slower than wall-clock time under EMulatR by design, so do not use two Ctrl/T lines to time something in real seconds.

 

Ctrl/\ and Ctrl/]: the trace hotkeys

These two are EMulatR's own keys, active only in a diagnostic build (RelWithDebInfo or Debug) started with EMulatR_DIAG_TRACE_HOTKEY=1. EMulatR takes them before they reach the emulated serial port, so the guest never sees them. In a release build, or without the setting, they are ordinary characters passed to the guest; neither the SRM console nor OpenVMS uses them. Full details: Console Trace Hotkey.

 

Terminal client notes

Some Telnet clients use Ctrl/] as their own escape key and never send it: the Windows telnet command, for example, opens its own command prompt instead. Use PuTTY (Telnet or Raw) for the console, which sends Ctrl/] as a character.

 

See Terminal Clients.

Any key reaches the guest only while a client is connected to the system's console port; the console serves one client at a time.
