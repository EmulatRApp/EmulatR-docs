EmulatR Version Numbering and Release Stages

EmulatR uses a single version identity across the console badge, the documentation, and the distribution kit. The format follows the Digital (DEC) convention familiar from SRM firmware version strings:

 

<stage><major>.<variant>-<build>

 

 Example:  X1.6-15

      Fields

 

      ┌─────────┬─────────┬─────────────────────────────────────────────────────┐

      │  Field  │ Example │                       Meaning                       │

      ├─────────┼─────────┼─────────────────────────────────────────────────────┤

      │ Stage   │ X       │ Release stage letter (see below)                    │

      ├─────────┼─────────┼─────────────────────────────────────────────────────┤

      │ Major   │ 1       │ Release series                                      │

      ├─────────┼─────────┼─────────────────────────────────────────────────────┤

      │ Variant │ 6       │ Tree generation, DERIVED (v5->5, v6->6)       │

      ├─────────┼─────────┼─────────────────────────────────────────────────────┤

      │ Build   │ 15      │ Incrementing build number, set manually per release │

      └─────────┴─────────┴─────────────────────────────────────────────────────┘

 

Release stage letters (DEC convention)

 

      ┌────────┬──────────────────────────────────────────────┐

      │ Letter │                   Meaning                    │

      ├────────┼──────────────────────────────────────────────┤

      │ X      │ Experimental (pre-release development build) │

      ├────────┼──────────────────────────────────────────────┤

      │ T      │ Field test                                   │

      ├────────┼──────────────────────────────────────────────┤

      │ V      │ Released                                     │

      └────────┴──────────────────────────────────────────────┘

 

  This is the same grammar a real Alpha console user knows from firmware strings such as V7.3-1, so a version shown by EmulatR reads exactly like one shown by genuine SRM firmware.

 

Where the version appears

     The version identity is emitted on the console banner when a terminal client attaches, above the emulated DEC firmware banner. That banner is EmulatR's own voice, not emulated firmware output:

 

      ASA EmulatR -- Alpha AXP (EV6 / 21264) Emulator

      Alpha Emulator Console X1.6-15

      (c) 2026 Timothy Peer / eNVy Systems, Inc.

 

     The same identity is carried by the documentation set and by the distribution kit, so a support question can always be tied to one exact build.

 

How the version is set (maintainers)

     There is exactly one source of truth. Both the numbers and the stage letter are declared in the project build file, and every other place the version appears is generated from it - the version is never typed in twice:

 

      CMakeLists.txt

        project(Emulatr VERSION 1.${EMULATR_TREE_VARIANT}.15 ...)  <- major . variant . build

        set(EMULATR_VERSION_STAGE "X")    <- stage letter X | T | V

 

     At build time those values are rendered into a generated header, which the console banner consumes; a build-time check confirms the badge and the header agree, so the two cannot drift apart. The build also mirrors the three numbers into this help project, so the manual and the emulator always report the same build.

 

     To raise the build number, edit the one version line and rebuild. To change release stage, flip the single stage letter: X during development, T for a field-test kit, V at release.
