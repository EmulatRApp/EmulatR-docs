Current Platform Support

A platform manifest describes the machine's device tree. It is named after the FIRMWARE IMAGE that actually loaded, not after the model name: firmware/ds20_v7_3.exe selects ds20_v7_3_platform.json. Keying the manifest to the firmware means the model and its firmware cannot drift apart, and a firmware variant can carry its own device set. The file is resolved next to the executable, not in the directory you launched from.

The selection order is: the EMULATR_PLATFORM_CONFIG environment variable if set, otherwise the name derived from the firmware image stem as described above.

 

A missing or invalid manifest does NOT stop the run. It falls back to the compiled-in default DS10 device tree, and the reason is printed, for example: PlatformConfig: using built-in default DS10 manifest -- "unsupported manifest_version 999 (expected 1)". This is worth knowing because a typo in the manifest name or a schema-version mismatch will not announce itself as a failure - the machine simply comes up as a DS10. If a platform behaves like the wrong model, check that line first.
