The Buffer Pool

The storage pool (storageLib/StoragePool.h) is a page cache that EMulatR owns and keeps resident. The emulator thread that runs the guest -- the vCPU -- only ever touches the pool's memory: it never holds a file handle, never issues a host call, and never takes a host page fault on disk data.

 

Memory

The pool is one allocation of pool_mb megabytes (default 512), divided into 4 KB pages. At start the pool:

•allocates on the NUMA node of the thread that creates it (the vCPU's node);

•tries Windows large pages, which are locked in memory, when the process holds the lock-pages privilege;

•otherwise raises the process working set and locks the allocation with VirtualLock;

•if neither succeeds, runs with ordinary pageable memory.

The run log names the outcome, for example STORAGE: pool 512 MB (131072 pages of 4096 B) on NUMA node 0 -- locked (VirtualLock); dump F:/....

 

Pages and frames

The page size is 4 KB. The guest addresses 512-byte sectors, so each page holds eight guest sectors, and requests may begin and end on any sector. The pool refuses an image whose size is not a whole number of pages, or that sits on a volume whose sector size does not divide 4 KB, because unbuffered 4 KB host I/O would then not be well-formed.

 

A frame maps one page of one disk to one buffer. A frame is Free, Filling (a host read is in progress), Valid, or Error. The frame always points at the newest version of its page.

 

Reads

•Hit: the page is copied out of the buffer. Nothing else runs.

•Miss: the page is handed to that disk's read worker, which fills the frame from the host; the vCPU waits for the fill. Guest time does not advance while it waits, so the outcome is the same however long the host takes.

 

Writes

•The guest's data is copied into the page. If the write covers only part of a page that is not resident, the page is first read from the host (read-modify-write), so a modified page is always fully valid. A write that covers a whole cold page needs no read.

•The write is then queued on the one machine-wide ordered queue (the MPW queue) as disk, page, version and a sequence number, and the writer thread takes it from there (see Storage Threading and Isolation).

 

Copy-on-write versions

If a page is rewritten while an earlier write of it is still queued, the new data goes into a new buffer. The frame moves to the new buffer (so the guest reads what it last wrote), and each queued entry still writes the buffer it captured. Writes A (first version), B, A (second version) therefore reach the host as A1, B, A2 -- never A2 in A1's place, which would break write ordering if the host failed between them.

 

Eviction

When a page is needed and none is free, a CLOCK (second-chance) sweep chooses a victim. Only clean frames are eligible: Valid or Error, not pinned by an in-progress request, and not referenced by any queued write or host call. A modified page is never evicted; it becomes clean once the writer has made it durable.

•cache_min_mb per disk: that disk keeps at least this much resident; the global sweep skips a disk at its minimum. It must hold one maximum-size transfer (128 KB).

•cache_max_mb per disk: that disk never holds more than this; when it reaches the cap it evicts its own pages first. 0 means no per-disk cap.

 

Back-pressure

max_pending_mb (default 64) bounds the data waiting in the MPW queue. When every resident page is modified or pinned, the next request waits for the writer to make a page clean. This costs wall time only -- guest time is frozen during the wait -- and is counted as a pressure stall.

 

Startup check

The pool refuses to start when pool_mb is not greater than max_pending_mb plus the sum of every disk's cache_min_mb, or when a disk's cache_max_mb is smaller than its cache_min_mb. On the pool engine a refused disk falls back to the direct engine, and the run log says why.

 

Statistics

At shutdown the run log carries one line of pool statistics, for example: Storage: pool at shutdown -- drained; reads H hit / M miss, F fills, E evictions, D durable pages in W host writes, R RMW fills, C COW, P pressure stalls. Durable pages divided by host writes is the coalescing factor.
