The reference count

With a fixed clock, no network and no console connection, a DS20 boot is fully deterministic: it executes exactly the same instructions every time, whatever the interrupt harness, JIT or snapshot settings. The instruction count at the end of startup must equal the reference:

Measure

Reference

Instructions retired at job terminated at

7,434,183,226

Cycles at the same point

9,968,538,995

Whole-boot PC hash (EMulatR_DIAG_PCHASH=1, JIT forced off)

0xff1c875f4942c7c7

A different count means the build changed what the guest executes. That is a failure to investigate before anything else, even if OpenVMS reaches Username:.

Tests

B-1 to B-8: boot

EMulatR_IRQ_HARNESS=1 V1_RUN_UNTIL=Username: bash v2.1/tools/v1_gate_run.sh B-2 out/build/v2.1-relwithdebinfo/run/EMulatR.exe on

For the Username: check, a console connects 20 seconds after the end of startup and sends a Return; connecting any earlier would change the count. The prompt can take several minutes to appear after that Return; this is a known fault and does not fail the test.

H-1: PC hash

Run B-3 with EMulatR_DIAG_PCHASH=1 on the RelWithDebInfo build. The hash printed at the end of startup must equal the reference above.

N-5 partner: DECnet

For the ES40 networking test N-5, a DS20 runs with networking on as the second DECnet node. Give it its own IP and DECnet address; do not use env-ds20pa for this, since its disks must stay identical to the golden set.

Pass

•OpenVMS startup completes: the STARTUP job reports job terminated at.

•After a Return at the console, OpenVMS prints the Username: prompt.

•No bugcheck, and no halt at the console.

•The instruction count at the end of startup equals the reference.
