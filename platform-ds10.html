AlphaServer DS10

The DS10 is a single-processor Tsunami system and EMulatR's original reference model. It is the uniprocessor control for every shared change: a change that alters DS10 behavior is suspect on every other model too.

Running a DS10

cd /d/EMulatR/project && v2.1/tools/EMulatR_launch.sh ds10 run

The platform argument sets the firmware, the memory ceiling and the model together, so they cannot disagree. The console listens on a TCP port and PuTTY opens on it.

 

Status

•The SRM console powers up and stops at the >>> prompt with every device present.

•OpenVMS V8.3 boots from the SCSI system disk (b dka0) through startup to the Username: prompt.

•Installing OpenVMS from the CD image has not been validated on the DS10 yet. Install on the DS20 and copy the disk.

 

SMP considerations

The DS10 has one CPU in hardware, so there is nothing to configure and nothing SMP will change about what it presents. It matters to SMP in another way: it is the control. When SMP lands, a one-CPU run must behave exactly as it does today, and the DS10 is where that is checked.
