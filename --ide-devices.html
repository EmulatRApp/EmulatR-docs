IDE Devices

On the DS10 / DS20 (Tsunami) the CY82C693 provides the IDE controller, exposed as two PCI functions on bus 0, slot 5, as on a real DS20E: function 1 is the primary channel (dqa, dqa.0.0.105.0 in show config) and function 2 the secondary (dqb, dqb.0.1.205.0). The console announces both at power-up: bus 0, slot 5, function 1 -- dqa -- Cypress 82C693 IDE and bus 0, slot 5, function 2 -- dqb -- Cypress 82C693 IDE. The primary channel interrupts on ISA IRQ14 and the secondary on IRQ15. Before 26 September 2026 only function 1 existed, so devices on the secondary channel were never found. IDE register / port behavior (the 0x1F0-0x1F7 primary and 0x170 secondary blocks, plus PCI config) and absent-slave probing are shared across the controllers.

 

ES40, ES45 and DS25 -- ALi M5229

The ES40, ES45 and DS25 use the ALi M1543C south bridge, whose IDE controller is the M5229. On the ES40 it is PCI device 15, function 0 (dqa.0.0.15.0 in show config); on the ES45 and DS25 it is function 1 of the south bridge's device. The same setting that selects the south bridge selects the IDE controller, so the two always match; the DS10 and DS20 get the Cypress instead. Both controllers share the ATA taskfile engine, so disks and the CD behave identically on either.

 

What the M5229 presents (as of 26 September 2026):

Feature

Behaviour

Identity

vendor 0x10B9, device 0x5229, revision 0xC1, class 0x0101FA (IDE, compatibility mode on both channels)

Interrupt pin

0x3D = 0x01 (INTA). In compatibility mode the primary channel interrupts on ISA IRQ14 and the secondary on IRQ15, through the south bridge's 8259 pair.

Base address registers

BAR I-IV reset to the datasheet's legacy values (0x1F1, 0x3F5, 0x171, 0x375) and size as 8, 4, 8 and 4 bytes of I/O. The taskfile still answers only at the fixed legacy ports; the BARs are what the guest reads back.

Bus-master registers

BAR V (reset 0xF001) places a 16-byte bus-master block, decoded while the Command register's I/O-enable bit is set. The status register's interrupt bit sets on every IDE interrupt and clears when written with 1.

ALi control registers

0x53 bit 3 hides BAR I-IV (they read 0) while it is set; 0x50 bit 1 selects whether the programming-interface bits 6:4 read as set. The timing, FIFO and Ultra DMA registers 0x40-0x7F hold what the guest writes, from the datasheet's reset values.

Earlier builds presented the M5229 with no interrupt pin, no base address registers and no bus-master block. That was enough for the SRM console, which polls the controller, but not for the OpenVMS driver, which waits for the interrupt. Installing OpenVMS on the ES40 from its CD still does not complete; see the ES40 platform guide.

 

Shared bus-master block

Both controllers carry the same bus-master IDE register block (SFF-8038i): at its base, the primary channel's command, status and descriptor-table pointer; at base + 8, the secondary's. EMulatR stores the command and descriptor pointer but performs no DMA: the active bit stays 0 and data moves only by programmed I/O. What the block does provide is the status register's interrupt bit, which the OpenVMS driver reads to recognise the interrupt as its own.
