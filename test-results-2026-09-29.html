Test Results: Boot Matrix, 29 September 2026

Every supported platform was booted to OpenVMS V8.3 under every combination of three settings: the interrupt harness (EMulatR_IRQ_HARNESS) off and on, the JIT (EMulatR_JIT) off and on, and a snapshot taken at the start of OpenVMS startup or none. Each run is unattended and starts from the same saved disks.

 

Status when this page was generated (29 September 2026 15:05): 24 of 24 runs complete, 24 passed. Runs marked Pending were still in progress.

 

What a pass means

•OpenVMS startup completes (the STARTUP job reports job terminated at).

•After a Return at the console, OpenVMS prints the Username: prompt.

•No bugcheck.

•DS20 only: the number of instructions executed up to the end of startup equals the reference count, 7,434,183,226. The DS20 runs use a fixed clock, no network and no console connection until startup ends, so every run must execute exactly the same instructions whatever the settings.

•

Build and setup

EMulatR X2.1-1, RelWithDebInfo build of 28 September 2026. Networking off (EMulatR_NET_ADAPTER=off), time-of-year clock fixed (EMulatR_TOY_MODE=fixed). Boot devices: DS20 dka0 (auto-boot), ES40 b dka200, DS10 b dka0. In these runs the JIT is on only when set; from the next build it is on by default.

DS10 notes

The first DS10 runs stopped short: the DS10 system disk's startup waited for an operator to mount a volume labelled TEST2 on DKA200, which holds the V8.3 disk. The startup was corrected on the disk and the DS10 runs were restarted on it; the results above are from the corrected disk.

The DS10 runs type the boot command and answer the console-update prompts over a live console connection, so their instruction counts vary from run to run and are not compared.

 

Late console connection (DS10)

Two further DS10 runs connect the console only after the SRM prompt appears, to test whether a console that connects late receives output.

Found during testing

•init after Ctrl/P does not reset the machine. The SRM init command returns to the prompt without re-initialising, and a following OpenVMS boot can halt with kernel stack not valid. For a clean boot, stop EMulatR and start it again.

•Slow first response to a late console connection. On the DS20, a console that connected after startup ended waited several minutes for the Username: prompt after pressing Return. Connect the console before booting.

•Snapshots. Taking a snapshot during startup did not change any run: DS20 runs with a snapshot executed exactly the reference count. Restoring a snapshot was not tested.
