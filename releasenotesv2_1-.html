2.1 (In Development)

The full User and Developer Reference is published online at https://EMulatRapp.github.io/EMulatR-docs/. It is the same guide the kit installs as documentation/EMulatRGuide.pdf, and it is updated with each release.

 

EMulatR 2.1 is in development. This page records what has changed since the T2.0-16 field-test kit, and becomes the release notes when a 2.1 kit ships. Entries are added as the changes land, so the page always describes the current development build.

 

Status at close of session, 27 September 2026

•AlphaServer DS20: OpenVMS V8.3 boots to the Username: prompt with the JIT off and on, and installs from its CD image (dqa1).

•AlphaServer ES40: requires HP's 67CLIPPER SRM console, V7.3-1, obtained as cl67srmrom.exe, prepared, and staged under its real name, es40_cl67srm.exe (see AlphaServer ES40, Console firmware); no other ES40 firmware works yet. The console starts cleanly on an EV68CB, and OpenVMS V8.3 boots from its SCSI system disk to the Username: prompt with the JIT off and on. Installing from the CD image does not complete yet; install on the DS20 and copy the disk.

•AlphaServer DS10: OpenVMS V8.3 boots from its SCSI system disk to the Username: prompt. With the CD image on the secondary IDE channel (dqb0) the installation kit boots and runs its startup, then stops before the installation menu. The cause is found: EMulatR presents the DS10 with the DS20's Cypress south bridge, but a real DS10 has the ALi M1543C. On the Cypress both IDE channels end up on interrupt 15, so the primary channel's driver takes the secondary channel's interrupts. The DS10 will present the ALi M1543C. Until then, boot the DS10 from its SCSI system disk and avoid its IDE devices; to install OpenVMS, install on the DS20 and copy the disk.

•AlphaServer ES45 and DS25: not supported in this build (the ES45 console stops starting its USB driver; the DS25 console runs but does not find its IDE disk).

•Next: the interrupt and timer delivery rework (interrupt work moved off the per-instruction path). The groundwork is in place: diagnostic builds can now report every interrupt source the current delivery path finds without being notified, and the new delivery core is designed and tested on its own. Phase 1 is now built behind a setting that is off by default (see Added): every notification is in place, and guest behaviour is unchanged with it on.

 

Added

•A selectable storage engine. The platform manifest key storage_engine chooses how writable disks are served. direct (the default) is the engine every previous release used. pool puts EMulatR's own resident page cache in front of each disk image, opens the images write-through so that a write the guest sees as complete is on the host device, and keeps the guest's writes in strict order across every disk. Settings: pool_mb, max_pending_mb, pool_dump_path, and per disk write_cache, cache_min_mb, cache_max_mb. If the pool cannot serve a disk, that disk falls back to the direct engine and the run log says why.

•Storage Engine chapter. A new chapter, 6.9 Storage Engine, explains how guest disk requests reach the host, the pool's threading and isolation, what each engine promises on a crash, a power loss or a host fault, and every storage setting.

•JIT memory fast path. With the JIT enabled (EMulatR_JIT=fused), ordinary loads and stores to RAM now run inline instead of through the full instruction path. Estimated about 12% less time to the login prompt on a DS20 boot. The JIT now runs by default (see JIT on by default).

•EMulatR_JIT_NO_MEMFAST. A new setting that turns off only the JIT memory fast path, for comparisons; the rest of the JIT stays on. The run log's JIT memfast: line shows whether the fast path is active and, if not, why.

•AlphaServer ES40 reaches the SRM console. The ES40 now starts HP's 67CLIPPER SRM console (V7.3-1) directly. The image it used before was the firmware-update build, which ran the update utility on every cold boot and never reached the prompt. The console completes its power-up tests and stops at P00>>> with every device present: pka0 (SCSI), ewa0, dqa/dqb (IDE) with the CD on dqa1, and dva0.

•AlphaServer ES40 runs OpenVMS. The ES40 now boots OpenVMS V8.3 from its SCSI system disk through startup to the Username: prompt, joining the DS10 and DS20. Its south-bridge devices now sit where a real ES40 has them: the PCI-to-ISA bridge at PCI device 7, the IDE controller at device 15 (console names dqa.0.0.15.0 and dqb.0.1.15.0), the USB controller at 19, and the power-management controller at 17. The network adapter moves to option slot 4 as ewa0.0.0.4.0.

•Guest networking configuration page. A new page under 5.9 Networking, Configuring Guest Networking (OpenVMS), gives the steps in order: binding the host adapter, planning unique IP and DECnet addresses, set ewa0_mode FastFD at the console, the LANCP commands for 100 Mb/s full duplex, the TCP/IP address, and checking the result with ping and a Wireshark filter for DEC traffic.

•Platform Guides chapter. A new section, 5.10 Platform Guides, has one guide each for the DS10, DS20 and ES40: the hardware EMulatR presents, devices, console firmware, how to run it, its current status, and what multiprocessor (SMP) support will mean for that model.

•Crash and JIT documentation. A new troubleshooting page, OpenVMS Crash or Hang: Capturing Diagnostics, gives the sequence for a bugcheck or hang: arranging a dump, analysing it with SDA on a copy of the disks, and the EMulatR diagnostic settings to pair with it. The JIT chapter, 5.8, now describes the JIT that ships: how to turn it on, what it compiles, when it stays off, and the run-log lines that report it.

•Console trace hotkey (diagnostic builds). With EMulatR_DIAG_TRACE_HOTKEY=1, pressing Ctrl/\ at the console starts a full instruction trace and Ctrl/] stops it, so a trace can be aimed at the moment a problem appears instead of starting at power-up. EMulatR takes both keys before the guest sees them. The run log reports the cycle and program counter where each window opens and closes. See the new page Console Trace Hotkey under 5.8 Logging & Diagnostics. Diagnostic (RelWithDebInfo) builds only; the Release build does not include it.

•ES40 firmware preparation. The AlphaServer ES40 page now explains, for users of the kit, which ES40 firmware file to obtain (HP's 67CLIPPER cl67srmrom.exe, V7.3-1), where the tested copy came from, how to check it by its SHA-256 hash, how to prepare it with a few PowerShell commands (no other tools needed), and the name it is staged under, es40_cl67srm.exe. The source tree adds tools/extract_es40_cl67.py, which does the same and refuses any other file.

•Wireshark and Packet Captures page. A new page under 9.2 Tools brings the Wireshark material together: the two ways to capture EWA0 traffic, how to find the guest's MAC address (at the console, in LANCP, from a DECnet address, and in a capture), the supplied EMulatR-EWA0 profile, and display and capture filter examples for watching one guest or one protocol (DECnet, LAT, OpenVMS Cluster, MOP, TCP/IP).

•Snapshot on request. Creating a file named EMulatR_SNAPSHOT in the run folder while EMulatR runs saves a full snapshot of the running machine, at the console prompt or with the operating system up, into the snapshots folder, without typing anything into the guest. EMulatR removes the file after each save, so it can be created again for another snapshot. EMulatR_SNAPSHOT_FILE names a different file to watch.

•Fixed-mode clock start date. EMulatR_TOY_FIXED_EPOCH sets the date and time the clock starts from when EMulatR_TOY_MODE=fixed, written YYYY-MM-DD, optionally followed by HH:MM or HH:MM:SS. The run log reports the date in use.

•Interrupt harness (on by default). EMulatR evaluates interrupts only when something has changed that could make one deliverable, instead of at every step. EMulatR_IRQ_HARNESS=0 restores the old per-step check; it is a diagnostic setting, not a supported configuration. Guest behaviour is identical: the certified DS20 boot retires exactly the same instructions with the setting on and off, with the JIT on and off. On that boot (Release build, JIT on) it takes 26% less time to the end of OpenVMS startup. It is on for the DS10, DS20 and ES40; the run log's IRQ harness: line shows its state.

•Platform Editor chapter. A new chapter, 3. Platform Editor, documents the Platform Editor (platedit_wx.exe): starting it, its window, editing a manifest, the Configure wizard, every validation message and troubleshooting. The chapters after Installation are renumbered: Quick Start is now 4, Operating EMulatR 5, Architecture & Internals 6, Reference 7, Troubleshooting 8, the Developer Reference appendices 9 and Performance 10.

•Platform Editor: Configure wizard. Tools > Configure... adds disks and a CD-ROM to an open manifest. It shows each controller's free units, offers the drive models in disk_types.json, creates new disk images when you press Finish (sized to whole 4 KB pages, as the storage pool requires), and can give the network controller its own MAC address. Edit > Undo Configure takes the change back; it never deletes image files.

•EWA0: a MAC address per system. The network controller's row in the platform manifest takes an optional mac, for example 02-5A-3C-11-90-4E. Without it the adapter keeps its default, 08-00-2B-E5-40-00.

 

Changed

•Systems name their identity; the ES40 console keeps its real name. A system's identity no longer comes from its firmware file name: the ini key [System] systemStem (for example es40_v7_3), or --system-stem on the command line, names its platform manifest, flash file, speed-up and badge profiles and log files; the firmware file's own stem is used only when neither is set. The launcher writes the key into every new system and adds it to an older system the first time it is opened, so the prepared ES40 console is now staged under its real name, es40_cl67srm.exe, and can no longer be confused with HP's update file es40_v7_3.exe. A pre-decompressed console .rom now binds its platform's flash exactly as the .exe does, and can sit in the firmware folder with no EMulatR_FLASH_ROM setting.

•Launcher: the flash file is no longer offered as firmware. The Firmware control listed a system's flash file (es40_v7_3.rom, the console settings) as a firmware image, often at the top of the list; choosing it stopped the emulator at once with decompressed.rom wrong size. It now lists a .rom only when it is a bootable pre-decompressed console.

•Launcher: several systems can run at once. Starting one system no longer disables Start for every other system. Each system still runs only once at a time, and two running systems cannot share a console port: the launcher names the system already using the port. Stop acts on the selected system, and closing the launcher offers to stop all running systems.

•Launcher: switching systems no longer carries the previous firmware. After selecting one system and then another, the Firmware control kept the first system's choice when the second system's firmware folder held a file of the same name; Configure then created and opened the first system's platform manifest inside the second system. Each system now shows its own firmware choice.

•Platform Editor: no reopened session. The editor no longer reopens the folder from its last session, and when the launcher opens it for a system it lists that system's manifests without loading one: select the manifest to work on. Before, it could show and save another system's manifest.

•Platform Editor: messages can be copied. Select a finding and press Ctrl+C, or right-click for Copy or Copy All, to put its text on the clipboard.

•Platform Editor: no false ES40 warning. The ES40 board map now includes the on-board power-management function (ALi M7101), so the editor no longer warns ali_pmu: hose 0 slot 17 is not a position on the AlphaServer ES40 Model 2 board.

•JIT on by default. The fused JIT now runs unless you turn it off: leaving EMulatR_JIT unset selects it, and the run log says JIT: fused (default). Set EMulatR_JIT=off (or 0) for the interpreter alone. Scripts that turned the JIT off by leaving the variable unset now get the JIT; set it to off explicitly.

•Firmware decompressor tool. The kit adds tools\host_firmware_decompressor.exe. With --rom it turns a compressed console image such as HP's cl67srmrom.exe into a pre-decompressed .rom that EMulatR loads directly, skipping the console's own decompression at every start. See Pre-decompressing the Firmware.

•Faster interpreter path. Per-instruction bookkeeping that ran on every retired instruction now runs only while a trace or breakpoint is active, and block execution checks for pending interrupts by reading a single word. Measure the gain on your own hardware.

•ES40 IDE controller presents its interrupt. The ES40's IDE controller (ALi M5229) now presents what the real part does: an interrupt pin, its base address registers at their reset values, and a bus-master register block. Its interrupts reach the processor on ISA IRQ14 and IRQ15, as on the DS10 and DS20. Earlier builds presented it with no interrupt at all, which the SRM console tolerates but the OpenVMS driver does not. The console output (show config, show device) is unchanged. The ES45 and DS25 share the model.

•Time-of-year clock modes. With EMulatR_TOY_MODE=fixed the saved CMOS store is no longer read or written, so every fixed run starts from the same clean clock and CMOS; earlier, a fixed run could pick up the store a previous fixed run left. In host mode (the default) the time now comes from the host clock at every start. Earlier builds reused the time saved at the last shutdown, and because guest time runs slower than host time, each boot began further behind the real date. The CMOS contents are still kept.

•DS10 and DS20: second IDE controller (dqb). The Cypress south bridge now presents its secondary IDE channel as PCI function 2, as the real part does, so drives and CD images on the secondary channel appear as dqb. show config lists Slot 05/2: Cypress 82C693 IDE dqb.0.1.205.0. Nothing on the primary channel (dqa) changes.

•Wireshark profile labels. In the supplied EMulatR-EWA0 profile the Unicast bookmark, button and coloring rule no longer say that unicast traffic is unexpected. EWA0 has carried real LAN traffic since the network backend arrived, so unicast is normal once the guest has peers. Re-import tools\wireshark\EMulatR-EWA0.zip to pick up the new labels.

•Fixed-mode clock default date. With EMulatR_TOY_MODE=fixed the clock now starts at 1 January 2027 instead of 1 January 2026. OpenVMS asks for the date during startup when the clock reads earlier than the time last saved on its system disk, so the fixed start date has to be later than the disk's last use. Set EMulatR_TOY_FIXED_EPOCH to choose another date.

•DS20 interrupt routing is built in. EMulatR now carries the DS20's PCI interrupt wiring itself, as it already did for the DS10 and ES40. The manifest's pci_irq_table_hose0 is only compared with it: a disagreement is logged at start-up and the built-in value is used.

•Platform Editor refuses devices EMulatR cannot run. Virtual tape (not yet supported), a second 53C810 SCSI controller and a second DE500 network controller are refused, and existing ones are reported as errors. A SCSI disk added with + Device now gets the drive model EMulatR-4G; before, it got EMulatR VIRTUAL DISK, which EMulatR does not attach.

•The launcher opens the new Platform Editor. Open in PlatEd and Configure now start platedit_wx.exe (the Qt edition only if it is missing) and pass the system's own Emulatr.ini, so the board view and the Configure wizard use that system's CPUs, memory and disk folder. The launcher also finds the emulator and the editor beside itself wherever the kit is installed.

•Platform Editor keeps disks in unit order. Storage rows are listed and saved in address order (channel, unit, LUN), so dka0, dka100, dka200 ... appear ascending in the tree, the bus diagram and the manifest. A manifest that was out of order is sorted when opened and marked changed. A disk added with + Device takes its place in that order. Two new warnings: a disk row with no media file still holds its address, so the next disk you add goes to another unit; and a disk with a LUN other than 0 is named dka<unit*100+LUN> at the console.

 

Fixed

•Large console pastes arrive complete. Pasting more than about 4 KB into the console used to lose the beginning of the paste without any warning. The console now applies flow control to the terminal, so a paste of any size is delivered complete and in order, at the guest's serial speed.

•Block execution after a VA_CTL change. Changing the virtual-address control register (VA_CTL) now also discards decoded instruction blocks, so no block decoded under the old setting can run under the new one.

•ES40 hands off to OpenVMS. After jumping to bootstrap code the ES40 console used to restart instead of starting the operating system. The console-to-bootstrap handoff now finds the correct PALcode routine on the ES40 console, so b dka200 -fl 0,1 reaches SYSBOOT> and OpenVMS V8.3 loads and begins startup. DS10 and DS20 are unchanged.

•Network adapter auto-detection. With EMulatR_NET_ADAPTER unset, EMulatR could refuse to attach EWA0 on a host that has one dedicated adapter, reporting several adapters have no bound address. The Windows WAN Miniport pseudo-adapters were being counted as candidates. They are now ignored, so the dedicated adapter is chosen automatically.

•ES40 console no longer reports a PALcode/CPU mismatch. The ES40 now presents an Alpha 21264B (EV68CB) processor, a part real ES40 systems shipped with, instead of an EV6. The 67CLIPPER console is built for EV67/EV68 processors and previously printed *** Warning - PALcode/CPU Mismatch - Reload SRM Firmware *** at every power-up; it now starts cleanly. The DS10 and DS20 are unchanged.

•ES40 OpenVMS startup no longer bugchecks. Startup used to stop with an INVEXCEPTN bugcheck in SYSMAN.EXE while it configured the IDE controller. EMulatR presented the controller as function 1 of a combined device; OpenVMS on the ES40 expects it as function 0 of its own PCI device, as on the real system board, and could not reach its configuration registers otherwise. The controller now sits at PCI device 15, function 0.

•DEC traffic filter on the guest networking page. The Wireshark display filter on Configuring Guest Networking (OpenVMS) listed its IP addresses without commas, which Wireshark 4.6 rejects. The addresses are now separated by commas.

•ES40 firmware name in the firmware folder readme. The readme placed in each system's firmware folder named es40_cl67.exe as the ES40 image. Under that name EMulatR finds no ES40 platform manifest and falls back to its DS10 platform, so the system could not start. The readme now names es40_cl67srm.exe and explains how to prepare it.

•Firmware integrity check documentation. The guide described [ROM]/firmwareSha256 as checking the firmware at load. The key is read but not yet enforced; the guide now says so.

•Version in the program banner and --help. The banner EMulatR prints when it starts said V4.0-0, and --help said V4, whatever the release. Both now show the release version, taken from the same place as the console badge.

•Stop reason after a requested stop. Stopping a run with the EMulatR_STOP file or Ctrl-C reported Stop reason: MaxCyclesExceeded with a meaningless fault code. It now reports Stop reason: StopRequested and the cycle count, and EMulatR exits with status 0.

 

Known limitations

•write_cache = ordered (write-back) is experimental. The default, off, is the recommended setting.

•On the pool engine, a host storage fault is reported in the run log, but the machine does not yet pause and offer resume or abort. A disk with write_cache = off holds the guest until the host recovers.

•A saved pool dump is not yet replayed automatically at the next start.

•CD and ISO media always use the direct engine.

•The Platform Editor validates the storage keys but has no control for storage_engine yet; set it in the manifest.

•The emulated SCSI disk does not yet support SYNCHRONIZE CACHE or FUA, and reports its write cache as disabled.

•ES40: show config shows an unreadable AlphaBIOS (ARC) version, and placeholder versions for the RMC and TIG.

•ES40: the second PCI bus (hose 1) is not yet available, so the SCSI and network adapters sit in option slots on hose 0. A real ES40 usually carries them on hose 1.

•EWA0: auto-negotiation settles on 10 Mb/s half duplex because the emulated adapter does not yet present a link partner. Select a fixed speed instead (set ewa0_mode FastFD, or LANCP /SPEED=100 /FULL_DUPLEX /NOAUTONEGOTIATE).

•EWA0: an instance whose manifest sets no mac presents the default hardware address, shared by every such instance. Give each system its own (the Platform Editor's Configure wizard can generate one), or do not put two such instances on one LAN unless they run DECnet Phase IV.

•ES40: installing OpenVMS from the CD (b dqa1) does not complete yet. The console boots the CD and OpenVMS starts to load, then waits indefinitely when it begins to use the IDE controller. Boot the ES40 from an installed SCSI disk instead.

•An IDE channel with no drives attached delays OpenVMS device configuration by several minutes: the driver waits out a timeout for each empty unit before continuing. The cause is traced to how EMulatR presents a channel with no drives: values written to its registers read back as if a drive were there, so the console and OpenVMS take each empty unit for a drive and wait for it. A correction is being prepared.

•ES40: only HP's 67CLIPPER SRM console, V7.3-1, works. HP ships it as cl67srmrom.exe, which must be prepared before use (its update packaging removed) and is staged as es40_cl67srm.exe. HP's ES40 firmware-update files (es40_vN_N.exe, including one named es40_v7_3.exe) are a different program and never reach the console prompt; the V7.2-1 and older 67CLIPPER consoles and the CLIPPER (EV6) console are not supported. The steps, the source of the tested file and its checksums are on AlphaServer ES40 (5.10 Platform Guides).

•Guest time runs slower than real time, so anything in OpenVMS that waits for a time interval takes correspondingly longer in real time. For example, MONITOR SYSTEM draws its screen at once but shows no figures until its first interval (3 seconds of guest time by default) has passed, which can take a minute or two. The figures then appear and update normally.
