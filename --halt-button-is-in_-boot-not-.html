Halt Button is IN, BOOT NOT POSSIBLE

Symptom

At power-up the console prints "Halt Button is IN, AUTO_ACTION ignored", and at the >>> prompt any boot attempt (for example b dqa1) is refused with "Halt Button is IN, BOOT NOT POSSIBLE".

 

What it means

The firmware reads the front-panel RUN/STOP (halt) switch and finds it asserted (IN). A halted machine refuses to boot and ignores auto_action -- on real hardware you would release the halt switch to allow a boot.

 

In EmulatR - RESOLVED

This was a real defect in EmulatR and it is FIXED. A normal machine now powers up with the halt switch released, honours auto_action, and accepts a boot at the >>> prompt. If you are reading this because you saw the message, see "If you still see this" below.

 

Root cause

The firmware reads the halt-switch state from a system-interface status register (smir, in the TIG register block). EmulatR did not model that register block at all, so reads of it fell through to the unmapped-space default of all-ones - every bit set, including the bit that means "halt switch asserted". The firmware was reading the machine correctly; the machine was lying to it. The fix was to model the TIG faithfully so the register returns real state.

 

Two plausible explanations were investigated and ruled out with evidence before the real one was found: a PALcode halt-switch flag, and an interrupt line being misread as a halt request. Neither was involved.

 

This is the textbook form of the most common class of emulator defect: an unmodeled region returns a value that looks plausible (all-ones or all-zeros), the firmware branches on it, and the symptom appears far away from the actual defect. It is why EmulatR's standing rule is that every register the console reads must be decoded and faithful.

 

What it used to look like

Kept for reference, since the message itself is genuine DEC console output you may meet on real hardware:

 

AlphaServer DS10 268 MHz Console V7.3-2, Feb 27 2007 13:25:53

Halt Button is IN, AUTO_ACTION ignored

>>> b dqa1

Halt Button is IN, BOOT NOT POSSIBLE

>>>

 

If you still see this

On a current build the message means the halt state is genuinely asserted, not that the register is floating. Check that the platform manifest for your machine actually loaded - an invalid or misnamed manifest silently falls back to the built-in default device tree, which can leave your machine without the device that supplies this register (see Current Platform Support). Report it if the machine is otherwise correctly configured.
